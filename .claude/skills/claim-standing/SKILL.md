# 주장 자격 검사

사용자 지적(2026-09-07): *"왜 매일 잘했다·더 수정할 게 없다·기다리기만 하면 된다·
오늘은 여기까지다 라고 하면서 다음날 실행하면 계속 문제가 나오는가."*

문제가 새로 생기는 게 아니다. **원래 있었고 안 본 것이다.**

## 주장별 자격 요건

### "전부 / 전수" 라고 말하려면

```
이름 기반 검색만 했나?        튜플 대입 / 다른 변수명 을 놓친다
목록·등록부와 대조했나?        그 목록 자체가 전수가 아닐 수 있다
**디렉터리를 다 봤나?**        패키지 하위 모듈을 통째로 빠뜨릴 수 있다
```
2026-09-10 비용 모델 정리에서 **하루에 세 번** "전부"를 잘못 말했다.
3차에서 `paper_engine/` 패키지 14모듈(생산 핵심)을 통째로 안 본 것이 드러났다.
-> 스캔 범위를 먼저 적고, 그 범위 밖은 "확인 안 함"으로 남긴다.

### "없다 / 죽었다" 라고 말하려면

한 지점만 보고 결론내지 않는다. [[cite-check]] 의 3종 대조를 거친다.
```
코드있음 + 켬 + 흔적없음  = 단절이지 부재가 아니다   (2026-09-11 DDM)
코드있음 + 끔             = 꺼진 것이지 없는 게 아니다
```

### "고쳤다 / 끝났다" 라고 말하려면

```
전수 조사를 했나                    표본이 다르면 결론도 다르다
조용한 실패를 감지할 수단이 있나     이 시스템의 기본값은 조용한 실패다
                                    출력이 사실을 주장하는데 그 주장을 검증하는 코드가 없다
같은 결함의 복사본을 찾았나          한 곳 고치고 닫았다고 두 번 오보한 적 있다
```
함수 하나를 성공 경로로 돌린 결과를 9단계 체인 전체의 결론으로 쓰지 않는다.
2026-09-04 "실측 PASS" 선언이 09-07 까지도 미검증이었다(배치가 그 지점에 도달 못 함).

### "기다리면 된다" 라고 말하려면

검증 지점과 **시각·요일**을 실측으로 적는다. 파일 / 키 / 기대값 / 언제.
트리거가 평일 전용인데 "내일 확인"이 토요일이면 검증은 오지 않는다.

## 하지 말 것

```
하루를 구조로 이야기하기      "막힌 층 셋" · "체계적 편차" 는 대개 이야기다
                             차단과 오기록은 함의가 정반대다
일치하는 기록을 증거로 세기    같은 계보면 하나의 주장이다. 문서·테스트·상수가 같이 틀린다
산출물의 자기 기술을 믿기      라벨·플래그·설명 문자열이 아니라 산식을 재현한다
```

## 쓸 수 있는 말로 바꾼다

```
"전부 고쳤다"        -> "X 범위에서 N건 찾아 고쳤다. Y 는 확인 안 했다"
"문제 없다"          -> "이 조건에서 재현 안 됐다. 다른 조건은 안 봤다"
"끝났다"             -> "검증 지점 Z 가 언제 나오면 끝이다"
```
