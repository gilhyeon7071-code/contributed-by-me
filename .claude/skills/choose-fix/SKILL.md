# 조치를 고르기 전

**"제일 싸다 / 위험이 작다 / 간단하다" 는 효과의 근거가 아니다.**
그것은 비용 비교이고, 비용으로 고르면 효과가 없는 쪽을 고를 수 있다.

## 이 스킬이 생긴 이유 (2026-09-12)

```
문제   장중 루프가 배치 락으로 95분 막힌다
조치   "백테스트 검증을 진입 뒤로 옮긴다" — 근거: "제일 싸고 위험이 작다"
결과   진입은 당겨졌지만 **락 점유 시간은 그대로였다.** 절반만 고쳤다
발견   내가 아니라 사용자가 "장시작은 상관없어?" 라고 물어서 드러났다
```
"진입이 늦다" 와 "루프가 막힌다" 를 같은 문제로 뭉갰고 앞의 것만 고쳤다.

## 1. 증상인가 원인인가

```
지금 고치려는 것을 한 문장으로 쓴다
그것이 사라지면 **관측되는 다른 증상들도 같이 사라지나?**
  같이 사라진다  -> 원인에 가깝다
  하나만 사라진다 -> 증상이다. 위로 한 단계 더 올라가라
```
증상이 여러 개인데 조치가 하나만 없앤다면, 그 조치는 **원인에 닿지 않았다.**

## 2. 이 조치가 그 원인에 실제로 닿는가

말로 "닿는다" 고 하지 말고 **기구(mechanism)** 를 적는다.
```
원인 X 가 결과 Y 를 만드는 경로:  X -> ... -> Y
내 조치가 그 경로의 **어느 칸**을 끊는가
```
끊는 칸을 못 적으면 그 조치는 추측이다.

2026-09-12 실패 예: 락 점유 -> 루프 차단 -> 발주 지연.
순서 교체는 이 경로의 **어느 칸도 안 끊는다**. 락은 배치 수명 전체 동안 잡혀 있다.

## 3. 효과 지표를 **먼저** 정한다  <- 가장 많이 빠뜨리는 단계

조치를 적용하기 **전에** 쓴다. 나중에 정하면 나온 결과에 맞춰 지표를 고르게 된다.
```
지표      지금 값  ->  기대 값      무엇이 재는가
지표 2    ...
반증      어떤 값이 나오면 이 조치가 실패인가
```
**지표가 없으면 비용으로 고르게 된다.** 그게 이 스킬이 생긴 이유다.

## 4. 기각한 대안은 측정으로 기각했나 추정으로 기각했나

```
대안마다: 기각 사유 + 그 사유가 측정인지 추정인지
추정으로 기각한 대안은 **살아 있다.** 조치가 실패하면 거기로 돌아간다
```
기각 사유를 안 적으면 다음 사람이 같은 대안을 다시 검토한다.

## 5. 이 판단이 틀렸다면 무엇이 알려주나

```
자동으로 드러나나        -> 좋다. 그 장치를 적는다
사람이 물어야 드러나나    -> 위험하다. 오늘이 그랬다
아무도 모르나            -> 조치 전에 관측 장치부터 만든다
```

## 6. 부작용 — 이 조치가 **끄는** 것은 무엇인가

```
방향이 느슨해지나 조여지나
같이 딸려오는 것이 있나 (입력을 공유하는 소비자)
되돌리는 방법은 무엇인가
```

## 적을 것 (조치 전에)

```
증상 / 원인      무엇을 고치는가, 왜 그것이 원인인가
기구             X -> Y 경로와 내가 끊는 칸
효과 지표        현재값 -> 기대값, 재는 도구
반증             어떤 결과면 실패인가, 그때 어디로 가는가
기각한 대안      사유 + 측정/추정 구분
부작용           방향, 딸려오는 것, 되돌리기
```

마치면 조치를 적용하고, **지표가 나오는 날짜를 적는다**
(트리거 요일 실측 필수 -> [[risk-path-edit]] 7번).
결과가 나오면 [[claim-standing]] 으로 "고쳤다" 를 말할 자격이 있는지 검사한다.
