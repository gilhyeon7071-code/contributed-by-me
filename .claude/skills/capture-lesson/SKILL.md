# 교훈을 어디에 적을 것인가

**"스킬로 만들까" 는 잘못된 첫 질문이다.** 목적지가 다섯이고, 스킬은 그중 하나일 뿐이다.
잘못 보내면 기록은 늘고 재발은 안 막힌다 — 이 저장소에 이미 메모 49개와 규약 24개가
있는데도 같은 실수가 반복됐다.

## 0. 먼저: 이게 교훈인가 사실인가

```
사실   "X 파일은 Y 를 한다" / "Z 는 2026-08-24 에 철회됐다"   -> 메모 또는 등록부. 끝.
교훈   "다음에 이런 상황에서 이렇게 해야 한다"                 -> 아래로 진행
```

## 1. 재발 가능한가

```
1회성 (그 파일 그 버그)         -> 기록만 한다. 절차로 만들지 않는다
재발 가능 (형태가 반복된다)      -> 계속
```
판단 근거: **이미 두 번 이상 일어났나.** 한 번이면 기록, 두 번이면 장치를 만든다.

## 2. 코드로 잡을 수 있나  <- 여기서 대부분 끝나야 한다

```
가능하면 **코드가 1순위다.** 문서는 내가 읽어야 작동하고, 코드는 내가 잊어도 작동한다
```
| 교훈의 형태 | 코드 장치 |
|---|---|
| 잘못된 값이 통과한다 | assert / 입력 가드 (정규화 **전** 원본에) |
| 산출물이 조용히 낡는다 | 신선도 검사 + 실패 시 fail-closed |
| 같은 실수를 여러 파일에서 | lint 규칙 / 공용 헬퍼로 단일화 |
| 시험이 공유 산출물을 건드린다 | 출력 경로 파라미터 + 회귀 테스트 |
| 감지기가 안 운다 | 합성 입력 테스트 |

**코드로 가능한데 문서로 보내면 그건 회피다.** 문서로 보내는 이유를 적을 수 있어야 한다
(예: 판단이 개입한다 / 자동 검사로 표현이 안 된다).

## 3. 문서라면 — 어느 문서인가

```
메모 (feedback_*)     짧은 원칙. "왜" 가 핵심. 내가 배경으로 들고 다닌다
                      -> 작업 시점을 특정할 수 없는 일반 원칙
스킬                  **작업 종류로 트리거되는 절차.** 시작 시점이 특정된다
                      -> "X 를 하기 전/하는 중" 이라고 말할 수 있으면 스킬
docs/references 규약   여러 사람·여러 도구가 따라야 하는 계약. 길어도 된다
                      -> 형식·임계값·정의처럼 참조되는 것
AGENTS.md             프로젝트 전체 규칙. **사용자 결정 사항이다.** 내가 임의로 안 고친다
```

### 스킬 자격 — 셋 다 만족해야 한다

```
1. 트리거가 말로 표현된다    "도구를 고칠 때" / "안 돌 때" / "수치를 낼 때"
2. 절차다 (순서가 있다)       사실 나열은 스킬이 아니다
3. 기존 스킬에 안 들어간다    들어가면 **병합한다.** 새로 만들지 않는다
```

## 4. 이미 있는 것의 중복인가

```
기존 메모/규약/스킬을 먼저 찾는다 (grep)
있으면 그것을 **고친다.** 새 파일을 만들지 않는다
있는데 안 지켜졌다면 -> 문제는 내용이 아니라 **트리거**다
                       내용을 다시 쓰지 말고, 여는 스킬을 만들거나 기존 스킬에 한 줄 넣는다
```
2026-09-11 실측: 규약은 24개 있었고 AGENTS.md 가 4개를 강제하고 있었다.
가장 넓은 `NEW_SIGNAL_VALIDATION_STANDARD.md` 는 아무도 안 불렀다. **없어서가 아니었다.**

## 5. 스킬 위생

```
개수가 늘면 트리거가 흐려진다. 설명이 겹치면 둘 다 안 열린다
새로 만들기 전에 기존 것에 섹션으로 들어가는지 본다
description 이 본체다 — "언제 여는가" 를 쓴다. 무엇을 하는지가 아니라
안 쓰이는 스킬은 지운다. 안 지키는 규칙은 규칙을 약하게 만든다
```

## 6. 어느 경우든 — 기록은 남긴다

PLANS 에 **무엇을 어디로 보냈고 왜 그 목적지인지** 적는다.
목적지 선택 자체가 나중에 검증 대상이 된다
(그 장치가 실제로 재발을 막았나 — 못 막았으면 목적지가 틀린 것이다).

## 요약 순서

```
사실인가          -> 메모/등록부. 끝
1회성인가         -> 기록만. 끝
코드로 잡히나      -> **코드.** 문서로 보내려면 이유를 적는다
시점이 특정되나    -> 스킬 (기존 것에 병합 우선)
계약인가          -> docs/references 규약
전체 규칙인가      -> AGENTS.md (사용자 결정)
그 외             -> 메모
```
