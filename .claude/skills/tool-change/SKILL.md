# 도구 변경 절차

순서대로 한다. 건너뛴 단계는 그날 안에 대가를 치른다 —
2026-09-11 에 "출력 경로 확인"을 빠뜨려 **같은 결함을 하루에 두 번** 만들었다
(자산 원장, account_basis 둘 다 `--out-dir` 을 무시하고 공유 `2_Logs` 에 썼다).

## 0. 고칠 값이 있나 — 잠금부터

```
옆에 *.lock.json 이 있으면 직접 편집 금지. 전용 도구로 바꾼다
백업은 잠금을 대신하지 못한다
```

## 1. 백업

```bash
cp tools/X.py "tools/X.py.bak_$(date +%Y%m%d_%H%M%S)"
```
경로를 나중 기록에 적는다.

## 2. 이 도구가 **어디에 쓰는지** 전수 확인  <- 가장 많이 빠뜨리는 단계

```
파일을 쓰는 모든 지점을 찾는다   write_text / to_csv / open(...,"w"/"a") / json.dump
각각이 --out-dir 을 따르나?      안 따르면 공유 SSOT 를 시험 실행이 덮어쓴다
전역 상수로 경로를 잡았나?        LOG_DIR / ROOT 직접 참조가 그 자리다
```
새 출력을 **추가**할 때도 같다. 기존 출력만 확인하고 넘어가면 오늘의 실수가 재현된다.

## 3. 새 산출물이면 형태를 먼저 정한다

```
날짜가 이름에 붙나?   붙이면 30일 뒤 사라진다. 결정에 쓰는 것은 날짜 없는 append-only 로
기준선이 데이터 자신에서 나오나?  그러면 항상 통과한다. 달력·투입원금 같은 외부 기준을 쓴다
모르는 값을 0 으로 채우나?        채우지 않는다. null 을 내고 status 를 적는다
```

## 4. 감지기는 **울리는지 시험한다**

경보·판정·게이트를 만들었으면 합성 입력으로 각 경우를 돌린다.
정상에서 침묵하는 것만 확인하고 끝내지 않는다 — **이상에서 우는 것**이 본체다.

```
정상        침묵해야 한다
이상 각각   울려야 한다 (경우마다 하나씩)
경계값      어느 쪽인지 정해져 있어야 한다
```
울지 않는 감지기는 없는 것과 같고, 매일 우는 감지기도 없는 것과 같다.

**결함을 되살려 시험할 때는 그 시험도 격리한다.** 재현할 결함이 '공유 경로에 쓰는 것'
이면 재현 자체가 그 결함을 실행한다. 2026-09-11 에 그렇게 공유 산출물을 덮어썼다.
**설계된 상태는 경보하지 않는다** — 이상만 경보한다.

## 5. 격리 실행

```bash
python tools/X.py --out-dir "<scratchpad>" [--no-alert] [--dry-run]
```
끝나면 공유 산출물이 안 변했는지 확인한다:
```bash
ls -la 2_Logs/<그 파일>   # 없거나 mtime 이 그대로여야 한다
```

## 6. 실제 실행

```
매매 시간인가?          장중이면 영향을 먼저 따진다
다른 배치가 도는 중인가?  락·동시성. 진행 중인 검증의 대상을 바꾸지 않는다
rc 와 산출물을 둘 다 본다  rc=0 이어도 산출물이 안 바뀌었으면 안 돈 것이다
```

## 7. 기록

PLANS 에 백업 경로 / 바꾼 이유 / 실측 결과를 적는다.
**검증 안 한 명령을 기록에 적지 않는다** — 다음 사람이 그대로 실행한다.

## 같은 결함이 여러 파일에 복사돼 있다고 가정한다

한 곳 고치고 "닫았다"고 말하지 않는다. 특징 문자열로 전수 검색한다.
이름·목록·**디렉터리** 셋 다 놓칠 수 있다 (패키지 하위 모듈을 통째로 안 본 적 있다).
