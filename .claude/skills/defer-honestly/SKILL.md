# 미루기 전에

**"급하지 않다" 는 순서를 정하는 말이지 제외를 뜻하지 않는다.**
그런데 실제로는 제외로 쓰여왔다. 2026-09-12 실측: 2026-08-31 이후 PLANS 본문에
보류 표현 187건("아직 안" 52 / "판정 대기" 70 / "나중에" 21 / "미검증" 17 / "남은 것" 14 / "보류" 9 / "미룬다" 4).

사용자 지적: *"급하지 않다 나중에 하자는 일이 수십 개 이상이야"*,
*"급하지 않더라도 결국은 해야 될 일"*.

## 미루려면 세 가지를 적는다. 못 적으면 지금 한다

```
1. 왜 지금이 아닌가
   **차단 사유여야 한다.** "우선순위가 낮다" 는 사유가 아니라 순서다
   유효한 차단: 프로세스가 실행 중이라 편집 불가 / 거래일이어야 측정 가능 /
               사용자만 실행 가능(슬래시 명령·권한) / 선행 결과가 있어야 판단 가능
   무효한 차단: 지금 대화 주제가 아니다 / 급하지 않다 / 작다 / 나중에 몰아서

2. 언제 하는가 — **날짜나 트리거로 적는다**
   "다음에" 는 날짜가 아니다. "루프가 멈추면", "09-14 장 마감 후" 는 트리거다
   트리거가 있으면 **그 트리거를 실제로 감시하는 장치**까지 만든다.
   감시 없는 트리거는 "안 함" 과 같다

3. 안 하면 무엇이 나빠지나
   적을 수 없으면 미루는 게 아니라 **버리는 것**이다. 버리기로 정하고 목록에서 지운다
```

## 하지 말 것

```

목록만 늘리기               미룬 것을 세는 장치를 안 만들면 목록은 자란다
할 수 있는데 미루기          지금 5분이면 되는 것을 "나중에" 로 보내지 않는다
사용자가 답 안 했다고 흘리기  제안했는데 답이 없으면 **판단해서 하거나 다시 묻는다.**
                           조용히 사라지게 두지 않는다 (2026-09-12 실제 사례)
```

## 세션을 닫기 전

미룬 것을 **세어서 보고한다.** 개수와 각각의 트리거를 같이 적는다.
```
이번 세션에 미룬 것 N건
  항목 | 차단 사유 | 트리거 | 안 하면 생기는 일
```
N이 3을 넘으면 그중 지금 할 수 있는 것이 있는지 다시 본다.
대개 있다.
