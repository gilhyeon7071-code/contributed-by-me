현재 작업은 read-only 배치 감사다. 수정 금지.

목표:
run_paper_daily.bat 및 관련 bat/ps1/python 실행 체인이
정확한 순서, 실패 전파, 산출물 최신성, 중복 실행 방지, FAIL-CLOSED 원칙을 만족하는지 검증한다.

반드시 확인할 것:

1. 배치 DAG 감사
- run_paper_daily.bat의 전체 실행 순서를 단계별 DAG로 작성한다.
- 각 단계의 입력 파일, 출력 파일, status JSON, latest 포인터를 정리한다.
- 같은 생성기/검증기가 중복 호출되는지 확인한다.
- 중복 호출 시 결과 덮어쓰기, 입력 변경, status 불일치 가능성을 보고한다.

2. exit code 전파 감사
- 각 bat/ps1/python 호출 뒤 errorlevel 또는 rc를 확인하는지 검증한다.
- 실패 rc가 상위 배치 실패로 전파되는지 확인한다.
- 실패했는데 WARN/continue 처리되는 단계와 즉시 중단되는 단계를 구분한다.
- exit /b 0으로 실패를 숨기는 경로가 있으면 HARD_FAIL로 보고한다.

3. 산출물 최신성 감사
- 각 단계가 생성해야 하는 JSON/CSV/parquet/log 경로를 확인한다.
- latest 파일이 실제 최신 timestamp 파일을 가리키는지 확인한다.
- 파일 mtime, as_of_ymd, run_id, generated_at이 서로 맞는지 확인한다.
- 오래된 latest를 재사용할 수 있으면 HARD_FAIL 또는 WARN으로 보고한다.

4. D 규칙 / 날짜 혼선 감사
- D가 fills.csv 최신 BUY 기준으로 계산되는지 확인한다.
- exec_date, as_of_ymd, run_id, signal_date, price date가 혼용되는지 확인한다.
- 휴일/주말 직전 거래일 계산이 HolidayManager 또는 SSOT를 쓰는지 확인한다.
- 자체 weekday 계산이 있으면 WARN 또는 HARD_FAIL로 보고한다.

5. FAIL-CLOSED 감사
- 필수 입력 누락 시 ALLOW로 흐르는 경로가 있는지 확인한다.
- orders_exec 없음, exec_date != D, as_of/run_id 불일치 시 중단되는지 확인한다.
- risk_off, kill_switch, gate BLOCK이 하위 단계에서 우회되지 않는지 확인한다.

6. 재시작/중복 실행 감사
- 같은 배치를 중복 실행했을 때 주문, 체결, 원장, stats가 중복 생성되는지 확인한다.
- lock 파일, run_id, idempotency key, order_id 중복 방어를 확인한다.
- 중간 실패 후 재실행 시 어느 단계부터 안전하게 재개되는지 확인한다.

7. 로그/상태 계약 감사
- run_paper_daily_last.txt가 실제 마지막 실행을 대표하는지 확인한다.
- 각 단계의 status JSON이 PASS/FAIL/WARN 의미를 일관되게 쓰는지 확인한다.
- 실패 사유가 대시보드/PLANS/운영 로그까지 전달되는지 확인한다.

- 위험도: HARD_FAIL / WARN / INFO
