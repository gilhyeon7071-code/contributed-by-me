## 1. 문제 — 장치는 있는데 걸리지 않는다

`tools/archive_final_score_snapshot.py:91-93` 에 중복제거가 있다.
```python
digest = _sha16(SRC)                       # CSV 파일 전체의 sha256
if not args.force and digest == _last_hash():
    print("[SKIP] 내용 동일")
    return 0
```
의도는 옳다. 그런데 **한 번도 걸린 적이 없다.**
```
manifest 288행,  sha256_16 고유값 288 / 288
signal_date 는 288행 전부 20260820 (하나뿐)
스냅샷이 찍힌 날: 08-22 23건 / **08-23(일요일) 235건** / 08-24 30건
```

### 원인 — 파일 전체를 해싱하는데 그 안에 시계가 들어 있다

연속한 두 스냅샷을 비교하면 **다른 컬럼이 3개뿐**이고 셋 다 시각에서 파생된다.
```
news_freshest_age_hours     117.875616 -> 117.908472     경과 시간(계속 증가)
news_reason                 문자열 안에 freshest_age_hours 가 박혀 있다
news_topic_l3_judgment_id   L3_20260823_120637_... -> L3_20260823_120836_...  실행 시각이 ID 에
```
**`final_score` · `final_score_base` · 축 값은 전부 동일하다.**
즉 "내용이 바뀌었다"는 판정이 **시계 때문에** 매번 참이 된다.

휴장일(08-23 일요일)에 235건이 쌓인 것이 그 결과다.

## 2. 변경 — 시각 파생 컬럼을 해시 대상에서 뺀다

파일 전체가 아니라 **의미 있는 내용**으로 해시를 만든다.
```python
TIME_DERIVED_COLS = (
    "news_freshest_age_hours",     # 경과 시간. 매 실행 증가한다
    "news_reason",                 # 위 값이 문자열로 박혀 있다
    "news_topic_l3_judgment_id",   # 실행 시각이 ID 에 박혀 있다
)
```
이 컬럼들을 제외한 나머지로 sha256 을 계산해 직전 값과 비교한다.
**제외한 컬럼은 파일에는 그대로 저장된다** - 해시 판정에서만 뺀다.

### 왜 화이트리스트가 아니라 블랙리스트인가
화이트리스트(축 컬럼만 해싱)로 하면 축이 아닌 의미 있는 변화
(`candidate_origin` 변경 등)를 놓친다. 블랙리스트는 **제외 근거가 증명된 것만** 뺀다 -
위 셋은 실측으로 시각 파생임이 확인됐다.

## 3. 곁들여 — asof 정체를 알린다

같은 `signal_date` 가 며칠째 이어지면 그 자체가 신호다.
후보가 08-20 에 멈춘 것을 아무도 몰랐고, 08-24 장중 매매 차단으로야 드러났다((80)B).
```
직전 매니페스트 행의 signal_date 와 같고, 그 상태가 N일 이상이면 경고 1줄
(기본 N=2, 환경변수 FINAL_SCORE_ASOF_STALE_DAYS)
```
**차단하지 않는다. 로그로만 알린다.**
