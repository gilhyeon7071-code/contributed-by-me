- 작성: 2026-08-19
- 상태: **초안. 사용자 승인 전이며 어떤 변경도 적용하지 않았다.**
- 분류: **매매 정책 변경** (AGENTS.md §5). §9 ExecPlan 필수, §11 E2E 증거 필수, §14 백업 필수
- 근거 기록: `.agent/PLANS.md` 2026-08-19 (17)(20)(21)(22)(23)(26)(28)

## 1. 왜 이 변경인가

### 1.1 SURGE가 손실의 94.4%다
청산 완료 포지션 330건, production 비용(왕복 0.358%) 기준:

| 경로 | n | 비중 | 순손익(원) | ROI |
|---|---:|---:|---:|---:|
| other | 107 | 32.4% | -144,650 | -0.06% |
| **SURGE** | 82 | 24.8% | **-1,197,980** | **-1.13%** |
| INTRADAY | 57 | 17.3% | -50,956 | -0.82% |
| **SURGE_RUNTIME** | 45 | 13.6% | **-55,769** | **-1.04%** |
| INTRADAY_REALTIME | 27 | 8.2% | -41,288 | -1.36% |
| beta_harvest | 12 | 3.6% | +162,540 | +2.10% |

```
전체          n=330   -1,328,102원   ROI -0.38%
SURGE 제외    n=203      -74,354원   ROI -0.03%
SURGE 기여    -1,253,748원 = 전체 손실의 94.4%
```
포지션의 **38.4%가 손실의 94.4%**를 만든다.

### 1.2 구조적 원인이 규명돼 있다
- **(23)**: SURGE는 직전 5일 **+20~24% 급등** 종목을 **20일 고점(+0.00%)**에서 산다. `SURGE_RUNTIME`은 체결가가 당일 종가보다 **+4.16% 높다**(매수 즉시 약 -4% 평가손).
- **(17)**: 실제 매수의 **37.1%가 vol_ratio 최상위 분위(D10)**이며 중립은 10%다. `SURGE_RUNTIME`은 **61.9%**가 D10이고, D10은 향후 20일 최악 분위(연 -11.44%)다.
- **(26)**: 급등·고점·거래량급증은 **한 종목에서 겹치며**, 통합 극단성 지표에서 최상위 분위가 -1.054%로 가장 나쁘다.
- **(28)**: SURGE 포지션은 `surge_exit_policy.stop_loss_pct = -0.03`이 적용되는데 해당 종목 일변동 중앙값은 **4.43%**다. 정상 변동만으로 손절이 발동해 보유 1일 → 연 252회전 → **연 90% 비용**을 만든다.
- **(22)**: `STOP_GAP`의 **73.3%가 SURGE**이며 실효 -3.00% 손절을 갭으로 뛰어넘어 -8.35%에 체결된다.

### 1.3 왜 손절 완화가 아니라 진입 축소인가
(28)에서 회전율 완화 방법 셋을 제시했다.
1. `surge_exit_policy.stop_loss_pct` 완화
2. `atr_stop_multiplier` 상향
3. **SURGE 진입 축소**

1·2는 **나쁜 종목군을 더 오래 보유하게 만든다.** (17)(23)(26)이 일관되게 그 종목군 자체가 향후 하회한다고 말하므로, 보유를 늘리면 손실이 커질 수 있다. 3번만 원인을 건드린다.

## 2. 변경 범위

### 2.1 대상
- `paper/paper_engine_config.json` 의 SURGE 진입 게이트 **설정값만**
- 코드 변경 없음
- **v41.1 후보 생성 경로 미접촉** (`execution_pool` 문제와 무관)

### 2.2 하지 않는 것
- SURGE 로직 삭제·비활성화 (되돌리기 어려움)
- 손절/청산 파라미터 변경 (별건)
- Gate·LOCK·risk_orch·kill_switch 의미 변경
- 운영 파라미터 `stable_params_v41_1.json` 변경

### 2.3 세 가지 후보안
| 안 | 방법 | 되돌리기 | 검증 난이도 |
|---|---|---|---|
| **A** | SURGE 진입에 `vol_ratio` 상한 조건 추가 (D10 제외) | 쉬움 | 중간 — 신규 지표 배선 필요 |
| **B** | SURGE 진입 임계 강화 (급등폭·거래량 요건 상향) | 쉬움 | 낮음 — 기존 파라미터 |
| **C** | SURGE 일일 진입 한도 축소 | 가장 쉬움 | 가장 낮음 |

**권고: C → B 순서.** A는 `vol_ratio`가 `EXPLORATORY` 상태((27): 봉인 OOS 확보 불가)라 근거가 가장 약하다. C는 기존 파라미터만 쓰고 즉시 되돌릴 수 있다.

## 3. 착수 전 확인 필요 (미해결)

**이 ExecPlan은 아직 실행 가능한 상태가 아니다.** 아래가 확인돼야 한다.

1. **SURGE 진입 게이트의 실제 파라미터 위치와 현재값.** 아직 특정하지 않았다.
2. **일일 진입 한도가 존재하는지.** C안의 전제다.
3. **SURGE 축소 시 자본이 어디로 가는지.** 현재 분석은 회계이지 반사실이 아니다. 남는 자본이 `other`(ROI -0.06%)로 가면 개선이지만 `INTRADAY_REALTIME`(-1.36%)로 가면 아니다.
4. **`config lock` 상태.** 2026-08-19 (별도 블록) 기준 `paper_engine_config.lock.json` 해시 불일치로 배치가 차단돼 있다. 설정 변경은 lock 재승인과 얽힌다.

- SURGE 진입이 2026-04부터 시작됐다(202512~202603은 0건). **효과 측정 구간이 5개월뿐**이다.
