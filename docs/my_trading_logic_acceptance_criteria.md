# 개인 기준 주식로직 평가표

## 목적

이 문서는 주식 자동매매 로직을 수익률만으로 판단하지 않고, 장기간 신뢰하고 운영할 수 있는지 평가하기 위한 개인 기준표다.

평가의 핵심 기준은 다음 한 문장이다.

> 잘 만든 주식로직은 수익이 난 로직이 아니라, 손실이 나도 망가지지 않고 원인 추적과 개선이 가능한 로직이다.

## 평가 원칙

- 사실은 코드, 로그, 파일 내용, 명령 출력으로 확인된 것만 사용한다.
- 증거가 없으면 `모름` 또는 `NA`로 판단한다.
- 추정으로 `PASS`를 주지 않는다.
- 수익률이 좋아도 재현성, 데이터 정합성, 리스크 차단이 약하면 좋은 로직으로 보지 않는다.
- 위험하거나 애매한 경우 FAIL-CLOSED 관점으로 판단한다.
- 정책 변경과 단순 개선은 분리해서 판단한다.

## 평가표

| 항목 | 배점 | 평가 기준 |
|---|---:|---|
| 재현성 | 20 | 같은 입력 데이터, 같은 기준일, 같은 설정으로 다시 실행했을 때 같은 후보, 주문, 결과가 나오는가 |
| 리스크 차단 / STOP 능력 | 20 | 거래하면 안 되는 상황에서 자동으로 멈추는가 |
| 설명 가능성 | 15 | 왜 종목을 골랐고, 왜 사고, 왜 팔고, 왜 쉬었는지 설명 가능한가 |
| 손실 원인 추적성 | 15 | 손실 원인을 시장, 종목선정, 진입, 매도, 체결, 데이터 중 하나로 좁힐 수 있는가 |
| 데이터 정합성 | 10 | D, as_of, exec_date, run_id, 주문일, 체결일, 장부 반영일이 섞이지 않는가 |
| 운영 자동화 / 유지보수성 | 10 | 수동 개입 없이 운영할 수 있고, 문제가 생기면 확인 위치가 정해져 있는가 |
| 수익성 / 기대값 | 10 | 단순 수익률이 아니라 반복 가능한 기대값이 확인되는가 |
| 합계 | 100 | 하드 FAIL이 없고 총점 기준을 만족하는가 |

## 하드 FAIL 조건

아래 조건은 총점과 관계없이 `FAIL`로 판단한다.

- `orders_exec` 없음
- `exec_date`와 D 기준일 불일치
- `as_of` / `run_id` 혼선
- `paper` / `broker` 날짜 혼용
- freshness HARD_FAIL 상태에서 주문 가능
- risk_off 상태에서 주문 가능
- 주문, 체결, 장부, 통계 연결 불일치
- 실행 결과 재현 불가
- 검증 실패를 무시하고 다음 단계 진행

## 최종 판정 기준

| 판정 | 조건 |
|---|---|
| PASS | 총점 80점 이상이고 하드 FAIL 없음 |
| WARN | 총점 60~79점 또는 핵심 증거 일부 부족 |
| FAIL | 총점 60점 미만 또는 하드 FAIL 존재 |
| NA | 입력 증거 부족으로 평가 불가 |

## 개인 판단 체크리스트

- [ ] 같은 입력으로 같은 결과가 나오는가?
- [ ] D / as_of / exec_date / run_id가 분리되어 있는가?
- [ ] 위험 상황에서 자동 STOP 되는가?
- [ ] 왜 매수했는지 설명 가능한가?
- [ ] 왜 매도했는지 설명 가능한가?
- [ ] 왜 쉬었는지 설명 가능한가?
- [ ] 손실 원인을 추적할 수 있는가?
- [ ] 수익률이 아니라 기대값이 검증되었는가?
- [ ] 수동 개입 없이 반복 운용 가능한가?
- [ ] 개선 포인트가 명확한가?

## 평가 출력 형식

### 1. 요약

사실:

- 제공된 로그, 파일, 명령 출력에서 확인된 사실만 적는다.
- 확인 불가한 것은 `모름`이라고 쓴다.

해석:

- 수익률보다 재현성, 리스크 차단, 원인 추적성을 우선 평가한다.
