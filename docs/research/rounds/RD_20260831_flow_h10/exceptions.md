- 조치: **데이터를 바꾸지 않는다.** 읽기 계약만 적는다 (예외 1과 같은 방침)

```
dtype                            indiv/forgn/inst _qty, _amt 6개 모두 **object(문자열)**
                                 값 예시 '-56722'
빈 문자열 '' 행                   약 8행 (0.02%)

정체                             전부 저가주 (close 460~1190). 해당일 수급 값이 비어 있다
```

## 왜 이것이 함정인가

`astype("float64")` 는 빈 문자열 하나에 **컬럼 전체가 예외로 죽는다.**
2026-09-12 에 `aftermarket_probe` 첫 구현이 정확히 그랬고, `try/except` 로 감싸 둔 탓에
**여섯 컬럼 합계가 통째로 비어도 조용히 넘어갔다.** 0.02% 가 100% 를 없앤다.

## 읽기 계약 — 이 라운드를 측정하는 코드는 반드시 이렇게 읽는다

```python
v = pd.to_numeric(df[col], errors="coerce")
total   = float(v.sum())          # NaN 은 합계에서 빠진다
dropped = int(v.isna().sum())     # **몇 개를 버렸는지 반드시 같이 보고한다**
```
`dropped` 를 보고하지 않으면 합계가 거짓이 된다. 버린 개수가 날짜/종목에 치우쳐 있으면
그 자체가 편향이다.

## 왜 쓰기 쪽을 안 고치나

`tools/fetch_investor_flow.py:122` 가 API 응답(문자열)을 그대로 `pd.DataFrame` 에 넣는다.
여기서 숫자로 변환하면 **이 라운드의 원자료 dtype 이 중간에 바뀐다** — 동결 구간이
09-12 전후로 갈린다. 예외 1과 같은 이유로 **바꾸지 않는다.**

지금 이 원장을 읽어 계산하는 소비자는 **없다**(실측: 다른 두 파일은 주석 언급뿐).
라운드 측정이 시작되기 전이므로 아직 피해가 없다.

## 판정 시 확인

```
측정 코드가 to_numeric(coerce) 를 쓰는가
dropped 개수를 보고하는가
dropped 가 특정 날짜·종목에 치우쳐 있지 않은가
```
