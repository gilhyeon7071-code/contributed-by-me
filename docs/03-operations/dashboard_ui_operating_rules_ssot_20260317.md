# Dashboard UI Operating Rules (SSOT)

Last updated: 2026-03-17  
Scope: `E:\vibe\buffett\dashboard.py`, `E:\vibe\buffett\dashboard_stock_v2.py`

## 1) 목적
- 투자 화면, 운영 화면, 전략 화면의 역할 혼합을 방지한다.
- 사용자 화면에서 개발/디버그/UI 셸 노이즈를 제거한다.
- 숫자/문구/상태/신선도/문제보드 표기를 고정 규칙으로 관리한다.
- 수정 후 복구 반복을 줄이고 재발 방지 기준으로 사용한다.

## 3) 화면 역할 분리 규칙
### 3.1 투자 화면
- 투자 화면은 결과 화면이다.
- 포함 가능:
  - 자산/수익/KPI
  - 자산곡선/낙폭
  - 포트폴리오/섹터 구성
  - 오늘 액션
  - 보유 종목 현황
  - 성과 지표
  - 데이터 신선도
- 포함 금지:
  - 내부 상태키 원문
  - 게이트 내부 필드명
  - 배치 로그 원문
  - 디버그용 경로/객체명

### 3.2 운영 화면
- 운영 화면은 상태/검증/원인 화면이다.
- 포함 가능:
  - 기준일
  - 실행ID
  - 단계상태
  - 다음 조치
  - 리스크 모드
  - 긴급 차단
  - 신호/주문/체결/보유 종목 수
  - 단계 진행 경과
  - 파이프라인 점검
  - 경고/실패 목록
- 포함 금지:
  - 투자 KPI를 메인 KPI처럼 배치하는 것
  - 내부키를 그대로 사용자에게 노출하는 것

### 3.3 전략 화면
- 전략 화면은 원인/품질 분석 화면이다.
- 포함 가능:
  - 백테스트/가상매매/실전 단계 비교
  - 전략 품질 지표
  - 진입/청산/사이징/리스크/필터 상세
- 포함 금지:
  - 운영 로그를 그대로 붙여넣는 것
  - 투자 화면용 요약을 중복 배치하는 것

## 4) 사용자 화면 노출 금지 규칙
아래 항목은 사용자 화면에 직접 보이면 안 된다.

### 4.1 개발 UI
- `Deploy`
- `Rerun`
- `Always rerun`
- Streamlit 상단 헤더/툴바/메뉴

### 4.2 내부키/엔진키
- `dashboard_state.*`
- `observer_state.*`
- `next_step=*`
- `pointer_ok`
- `orders_contract_ok`
- `config_snapshot_match`
- `risk_recent_ok`
- `lvb_recent_ok`

원칙:
- 내부키는 사용자용 문장으로 치환한다.
- 운영 화면에서도 “설명” 문장으로 먼저 보여주고, 원문키는 기본 숨김 상태로 둔다.

### 4.3 아이콘 문자열
- `keyboard_double_arrow_right` 같은 문자열은 사용자 화면에 보이면 안 된다.
- 우선순위:
  1. 앱 셸/런처 원인 제거
  2. 대시보드 CSS에서 머티리얼 아이콘 폰트 강제 적용
  3. 사이드바 접기 컨트롤 숨김

## 5) 상단 정보 위계 규칙
투자 화면 상단은 아래 순서로 고정한다.

1. 현재 화면명
2. 기준일
3. 검증 상태
4. 다음 조치
5. 알림 건수

추가 규칙:
- 한 줄 요약 문장을 함께 둔다.
- 상단에 브랜드명/플랫폼명을 반복 노출하지 않는다.
- 동일 화면에서 큰 타이틀 2회 반복 금지

## 6) 문제/원인/조치 보드 규칙
- 보드 제목은 `문제/원인/조치`로 고정한다.
- 투자 화면에서는 표보다 핵심 FAIL/WARN 카드가 먼저 보이게 한다.
- 목록은 `문제목록열기(n건)` / `문제목록닫기(n건)` 토글 1개로만 제어한다.
- 개별 항목별 펼침 구조 금지

표기 규칙:
- `상태`
- `문제`
- `원인`
- `조치`

원칙:
- `원인`은 내부키가 아니라 사용자 문장으로 적는다.
- `조치`는 바로 실행 가능한 배치/복구 행동으로 적는다.

## 7) 숫자/결측/코드 표시 규칙
상세는 `ui_numeric_display_rules.md`를 따른다. 여기서는 대시보드 화면 규칙만 고정한다.

- 총자산/손익/체결금액: `원` 또는 `억/만` 축약 표기
- `?1.00억`, `?0` 같은 문자 깨짐 금지
- 결측 표기는 `-` 또는 `NA` 중 화면별 1종으로 통일
- 승률은 `+19.44%`처럼 부호를 붙이지 않는다.
- 주식 코드는 6자리 zero-pad 고정

## 8) 언어/문구 규칙
- 카드 제목은 한 화면 안에서 한글 우선으로 통일한다.
- 영어는 고유명/브랜드/모델명 외에는 기본 금지
- 내부명은 사용자용 용어로 치환한다.

예:
- `next_step` -> `다음 조치`
- `risk_mode` -> `리스크 모드`
- `kill_switch` -> `긴급 차단`
- `signals / orders / fills` -> `신호 / 주문 / 체결`

## 9) 타이포/메뉴 위계 규칙
상세는 `ui_typography_hierarchy_rules.md`를 따른다.

추가 고정:
- 메뉴는 네비게이션 역할만 수행한다.
- KPI보다 메뉴가 먼저 눈에 띄면 실패다.
- 활성은 배경/보더로 강조하고, 비활성은 대비/웨이트를 낮춘다.
- 투자 화면에서 좌측 메뉴가 역할 분리를 방해하면 요약 패널로 대체 가능하다.

## 9.1) 요약 카드 정규화 기준
- 적용 대상: `운영`, `로직판정`, `시스템헬스` 요약 카드
- 카드 제목: `14px / 700`
- 카드 값(일반): `18px / 600`
- 카드 값(compact): `16px / 500`
- 카드 힌트: `12px / 400`
- 카드 상세: `13px / 400`
- HTML 표 헤더: `12px / 700`
- HTML 표 본문: `12.5px / 400`
- HTML 표 캡션: `12px / 400`
- HTML 표 셀 패딩: `8px 10px`
- HTML 표 line-height: `1.35`
- 이 기준은 `dashboard.py`의 `op-spec-card` 계열에 우선 적용한다.
- 이후 같은 역할 카드가 추가되면 기본 markdown 크기를 따르지 말고 이 기준에 맞춘다.
- 전략 세부검증 표처럼 `st.dataframe`에서 폰트 제어가 안 되는 구간은 HTML 표를 우선 적용한다.
- HTML 표 전환 후에는 헤더/본문/캡션을 위 기준값으로 고정한다.

## 10) 차트/해석 규칙
- 자산곡선/낙폭은 단순 그래프만 두지 않는다.
- 최소 1줄 해석 문장을 함께 제공한다.
- 가능하면 아래를 포함한다.
  - 레짐 오버레이
  - 벤치마크 비교
  - 이벤트 마커
  - 포지션 수 연동

해석 규칙:
- 낙폭이 크면 방어 우선 문구
- 누적수익이 플러스면 추세 유지 여부 문구
- 데이터 부족이면 “해석용 데이터 부족” 문구

## 11) 데이터 신선도 규칙
투자 화면에도 신선도 카드가 있어야 한다.

필수 카드:
- 리스크 기준
- 비교 자료
- 주문 파일

표기 규칙:
- `최신`
- `하루 지연`
- `n일 지연`
- `대체 파일 사용`
- `직접 생성`

원칙:
- stale 개념은 운영 화면에만 숨기지 않고 투자 화면에서도 읽히게 한다.

## 12) 이름/한글 인코딩 복구 규칙
- 깨진 이름 캐시는 신뢰 소스로 쓰지 않는다.
- 이름 소스 우선순위:
  1. `E:\1_Data\2_Logs\candidates_latest_data.csv`
  2. `E:\1_Data\_cache\dart_corp_code_map.csv`
  3. 정상 상태의 orders 산출물
  4. 마지막 정상 name cache

원칙:
- 이름/섹터 문자열이 깨졌으면 화면에서 강제로 정상값으로 치환한다.
- 복구 불가 시 `코드-xxxxxx`, `섹터 확인 필요`로 표시한다.
- 깨진 이름을 cache에 다시 덮어쓰지 않는다.

## 13) 수정 우선순위 규칙
화면 문제는 아래 순서로만 처리한다.

### P0
- 개발 UI 노출 제거
- 숫자 표시 오류 제거
- 내부키 노출 제거
- 역할 혼합 제거

### P1
- 상단 정보 우선순위 재정렬
- 문제/원인/조치 보드 강화
- 메뉴 영향력 축소
- 한글/문구 체계 통일

### P2
- 차트 해석 강화
- 데이터 신선도 표시
- stale/lag 시각화

원칙:
- P0 미해결 상태에서 P2 디자인 확장 금지

## 14) 실행/복구 규칙
- 화면 수정은 소규모 패치만 허용
- 패치 후 즉시 `py_compile` 검증
- 필요 시 대시보드 프로세스 재시작 후 확인
- 화면 기준 완료 판정

추가 규칙:
- 문제 해결 후 `dashboard_state_latest.json` 상태를 함께 확인한다.
- `overall`, `alerts_count`, `orders_contract_ok`, `lvb_recent_ok` 등 핵심 상태는 수정 보고에 포함한다.

## 15) 완료 판정
아래를 모두 만족하면 완료로 본다.

1. 사용자 화면에서 개발 UI가 보이지 않음
2. 숫자/결측/코드 표기가 규칙과 일치함
3. 투자/운영/전략 역할이 섞이지 않음
4. 문제/원인/조치 보드가 사용자 문장으로 읽힘
5. 신선도/상태를 3초 안에 파악 가능함
6. `py_compile` 통과

## 16) 후속 개선 관리
- 이번 문서에 없는 개선안은 바로 규칙으로 승격하지 않는다.
- 먼저 “추가 개선사항” 목록으로 관리하고, 2회 이상 반복 요청되거나 재발 방지 효과가 명확할 때 규칙 문서에 편입한다.
