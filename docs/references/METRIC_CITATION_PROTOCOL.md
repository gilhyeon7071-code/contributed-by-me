# 지표 인용 규약 (METRIC CITATION PROTOCOL)

- 제정: 2026-08-20
- 근거: `.agent/PLANS.md` 2026-08-20 (85) — 같은 양(후보 수)에 숫자가 셋 존재하고 6.5배 이상 벌어졌다
- 선례: PLANS 2026-08-15 (8) 블록의 후보 수 측정 규약. 본 문서는 그것을 전 지표로 확장한 것이다

## 왜 필요한가

**같은 이름의 지표가 조건에 따라 몇 배씩 달라진다.** 조건을 안 적으면 다른 기록과 비교할 수 없고,
비교할 수 없으면 축적되지 않는다. 검증을 아무리 해도 완성된 자료가 나오지 않는 이유다.

실제 사고:
- **후보 수**: 래더 적용 여부만으로 6.5~12배 (13일 <-> 159일)
- **진입 통과율**: 후보 수(165)와 날짜 수(11)를 나눠 "6.7%"라는 없는 수치를 만듦 (PLANS (35) B항)
- **final_score**: 같은 종목 같은 날 세 파일에서 값이 다르고 순위가 역전됨 (PLANS (74))
- **stable 인증 수치**: 저장값 재채점(oos_pf 1.464)과 재계산(0.785)이 다름 (PLANS 2026-08-15 (3))

## 공통 규칙

1. **수치를 적을 때 조건을 같은 줄 또는 바로 아래에 적는다.** 나중에 찾을 수 있게가 아니라, 인용문과 붙여서.
2. **조건이 하나라도 빠진 수치는 인용하지 않는다.** "대략 이 정도"로 쓰지 않는다.
3. **다른 기록의 수치를 인용할 때 조건이 없으면, 그 사실을 명시한다** (예: "조건 불명").
4. **집계 단위를 먼저 확정한다.** 분자와 분모의 단위가 같은지 확인한다.
5. **비율을 만들 때 분자·분모의 출처 파일을 각각 적는다.**

## 지표별 규약

### 1. 후보 수 / 후보 발생일

| 명시 항목 | 이유 |
|---|---|
| 측정 창 (시작~종료, **세션 수**) | 달력일과 거래일이 다르다 |
| **래더 적용 여부** (L0 단독 / L0~L9 순회) | **6.5~12배 차이** |
| **섹터 유니온 폴백 포함 여부** | 포함 시 후보가 크게 늘고, 생산은 이를 observe-only로 제외한다 |
| 파라미터 출처 (`stable_params` / `DEFAULT_PARAMS` / 수동) | `w_tech_score` 등은 stable에 없어 DEFAULT가 쓰인다 |

**금지**: 래더 미명시 인용. 생산 후보 수와 시뮬레이터 후보 수의 혼용.

### 2. 진입 통과율 / `entry_ready`

| 명시 항목 | 이유 |
|---|---|
| **집계 단위** (실행 단위 / 종목-일 단위 / 날짜 단위) | 단위가 다르면 비율이 성립하지 않는다 |
| **카운터 리셋 주기** | `entry_ready`는 **1회 실행당** 카운터다(`entry.py:6413`). 일자 합계와 다르다 |
| `max_new` 값 | `max_new<=0` 이면 `candidates_after_caps` 가 **0으로 강제**된다(`positions.py:1372`) |
| 관측 구간의 실행 횟수 | 하루 약 41회 실행된다 |

**금지**: 분자와 분모의 단위가 다른 비율. (사고: 후보 수 165 / 날짜 수 11 = "6.7%")

### 3. 게이트 통과율

| 명시 항목 | 이유 |
|---|---|
| 측정 창 + 표본 수 (종목-일) | |
| **단일 조건인지 AND 결합인지** | 개별 90%가 열 개면 AND는 35%다 |
| 파라미터 값 (임계 그대로 적기) | 임계가 바뀌면 통과율이 바뀐다 |
| 패널 출처와 필터 | `close>0` 미적용 시 결과가 뒤집힌다 |

### 4. `final_score` / 순위

| 명시 항목 | 이유 |
|---|---|
| **어느 파일인지** | `candidates_latest_data.csv`(base) / `.with_final_score.csv`(사이드카) / `pending_entry_status.entry_decision_rows` — **셋의 값이 다르다** |
| **축 구성** | 2026-08-20 이후 `final_score_axis_mode` 컬럼으로 식별한다 |
| 조정항 포함 여부 | `execution_lob_adjustment`(가산) / `medium_news_adjustment`(승산, 08-20~) |
| 측정 시각 | 사이드카는 배치 중 재생성된다. 오전 사본과 오후 판정은 다르다 |

**금지**: 파일 미명시 인용. **엔진이 쓰는 것은 사이드카**이며 base 가 아니다(`entry.py:10332`).

| 명시 항목 | 이유 |
