## 작업 원칙
- 사용자가 요청한 범위만 작업한다.
- 요청하지 않은 개선, 확장, 재설계, 비교, 추가 설명은 하지 않는다.
- 확인 가능한 것은 먼저 직접 확인하고, 승인 전에는 범위를 넓히지 않는다.
- 추정으로 완료라고 말하지 않는다.
- 실제 화면, 실제 산출물, 실제 결과를 확인한 뒤에만 완료라고 말한다.

## 수정 원칙
- 기존 파일 수정 전에는 반드시 백업부터 만든다.
- 백업 경로와 파일명을 먼저 명시한다.
- 한 번에 넓게 건드리지 말고 요청한 대상만 최소 범위로 수정한다.
- 하드코딩으로 상태, 점수, 완료도, 결과를 올리지 않는다.
- 로직 수정 없이 수치만 좋아 보이게 만드는 변경은 금지한다.
- 표시 수정과 원인 해결을 구분해서 보고한다.

  3. 다음 진행사항

## 검증 원칙
- 코드 수정 후에는 가능한 범위에서 문법 검증, 실행 검증, 화면 검증을 한다.
- checking_logic 검증은 `문법 -> manifest 생성 -> auditor` 순서를 고정한다.
- 배치 엔트리포인트는 조기 실패를 포함해 `run_start`/`run_end` 종료 로그를 남겨 원인 추적 가능 상태를 유지한다.
- 화면 관련 작업은 실제 화면 기준으로 비교한다.
- 규칙 적용 여부는 문서 기준이 아니라 실제 보이는 결과까지 확인한다.
- HTTP 200만으로 완료라고 판단하지 않고, 실제 화면에서 블록 수, 제목, 위계, 접힘 구조까지 확인한다.
- 화면 구조 수정 중 발생한 Python 예외는 표시 문제로 넘기지 말고, 예외명과 변수명 기준으로 원인 해결 여부를 따로 확인한다.
- 검증 없이 `반영됨`이라고 단정하지 않는다.

## UI 작업 원칙
- 기준 화면을 먼저 고정한다.
- 이후 다른 화면은 그 기준에 맞춰 동일한 방식으로 맞춘다.
- 탭 수를 줄이거나 재배치할 때는 실제 화면 캡처 기준으로 기준 탭 구조를 먼저 고정하고, 다른 탭도 같은 방식으로 맞춘다.
- 현황판은 기존 `dashboard.py` 안의 첫 탭으로 유지한다.
- 현황판은 `한눈에 전체 상태 파악 / 빠른 네비게이션 / 핵심 지표 요약 / 이상 징후 즉시 확인` 역할로만 사용한다.
- 현황판은 요약 전용 첫 화면으로 두고, 상세 근거와 긴 표는 다른 탭으로 내린다.
- 현황판의 외부 지표는 `현재값 + 전일대비 변화` 중심으로 표시한다.
- 현황판의 활성 포지션은 실제 가상매매 오픈 포지션 기준을 우선한다.
- 요약 탭에는 핵심 결론과 우선순위만 두고, 근거표, 추적표, 규칙표, 운영 점검표 같은 보조 정보는 세부검증으로 내린다.
- 서로 다른 평가층의 정보는 같은 요약 영역에 섞지 않는다.
- 로직판정 `세부검증`은 `결론 -> 판단근거 -> 세부검증 -> 원본근거` 순서로 구성한다.
- 로직판정 `세부검증`의 기본 상세 노출은 `운영문제/변경값/모듈진행` 중심으로 제한하고, 원본 경로/규칙은 `원본근거` 접힘에서 확인한다.
- 일부만 흉내 내는 방식으로 처리하지 않는다.
- 텍스트 작업이면 텍스트만 다루고, 구조나 로직으로 범위를 넓히지 않는다.

## 신호체인 정규화 고정 기준 (2026-04-02)
- 아래 6개 항목은 `작업 시 인용 기준`으로 고정한다.
- 수정/검증/보고 시 해당 항목을 기준으로 적용 여부를 명시한다.

1. 상태값 체계 정규화
- `PASS / FAIL / PARTIAL / WARN / NOT_EVALUABLE` 의미와 승격 조건을 공통 규칙으로 사용한다.
- 동일 상태값이라도 `차단 여부`를 함께 기록한다.

2. 품질→차단 매핑 정규화
- `news_collect`, `news_score`, `macro freshness` 품질 상태를 `ALLOW / REDUCE / BLOCK`으로 매핑해 사용한다.
- 품질 실패를 단순 경고로만 두지 않는다.

3. 단계 간 정합성 정규화
- 후보생성/신호합성/엔진의 `asof_ymd`, `regime`, `universe` 불일치 여부를 공통 항목으로 검사한다.
- 불일치 허용 범위와 실패 기준을 같은 규칙으로 사용한다.

4. 제안값 적용 정책 정규화
- `현재값 / 변경값(제안) / 변경값(적용후)`의 의미를 분리한다.
- 적용 시점, 적용 조건, 미적용 표기 규칙을 고정한다.

5. 검증 완료 기준 정규화
- 완료는 `감지 -> 승격 -> 차단 -> 재현검증` 1세트 확인 후에만 판단한다.
- `감지됨`과 `원인 해결됨`을 같은 상태로 보고하지 않는다.

6. 대시보드 표시 규칙 정규화
- 화면 `정상` 표시는 실제 차단 조건과 모순되지 않을 때만 사용한다.
- 표시 상태와 실제 실행 상태가 다르면 표시 상태를 우선하지 않는다.
