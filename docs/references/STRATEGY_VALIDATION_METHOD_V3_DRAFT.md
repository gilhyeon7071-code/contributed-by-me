# 후보 생성 검증 방법론 V3 — 독립 입력·세 층 검증 초안

> 상태: **DRAFT — 아직 현재 V2 가드를 대체하지 않음**
>
> 목적: 기존 운영 로직의 변수·Gate·후보 파일을 정답 또는 발견 입력으로 쓰지 않고, 독립적인 후보 생성 방법을 검증한다.

## 1. 변하지 않는 실행 계약

- `PRICE_HISTORY_INTEGRITY_V1`
- 일자별 KOSPI/KOSDAQ 보통주 모집단과 상장·상폐·거래정지 이력
- 신호일 종가까지 알 수 있는 정보만 사용
- 실제 전역 거래일 기준 다음 시가 진입 가정
- 사전 고정 비용·슬리피지·세금
- Train → Validation → OOS 시간 분리
- 연구와 Gate·LOCK·주문·체결·원장·브로커·운영 paper runtime의 분리

## 2. 입력 출처 격리

모든 입력은 다음 중 하나를 반드시 기록한다.

1. `RAW_INDEPENDENT`: OHLCV, 거래대금, 시가총액, 섹터, 공시·뉴스, 상장·상폐·거래정지 등 원천 자료
2. `RESEARCH_DERIVED`: 원천 자료에서 V3 연구 코드로 재계산한 수익률·변동성·순위·상관·레짐
3. `LEGACY_CONTROL_ONLY`: 현 RS, v_accel, final score, 기존 레짐, Gate 파생값 등

발견 단계의 후보 규칙에는 `RAW_INDEPENDENT`와 `RESEARCH_DERIVED`만 사용한다. `LEGACY_CONTROL_ONLY`는 같은 계약에서 비교하는 통제군으로만 사용한다.

### 2.1 발견 후보 사전오염과 레거시 중복 통제

- 신호 후보 목록은 라운드 시작 전에 `feature_dictionary_id`, 파일 SHA-256, 동결 시각으로 고정한다. 실행 뒤에는 목록을 수정하지 않고, 추가·삭제는 다음 탐색 라운드의 새 사전등록으로만 허용한다.
- 각 신호에는 원천 입력, 계산식, 방향 가설, 경제적 근거, 최초 제안 출처, `LEGACY_ADJACENCY` 판정(`NONE` / `SIMILAR_BUT_INDEPENDENT` / `LEGACY_REDUNDANT_OR_REVIEW` / `LEGACY_DERIVED`)을 기록한다.
- `LEGACY_DERIVED` 신호는 독립 발견군에 넣을 수 없고, `LEGACY_CONTROL_ONLY` 통제군으로만 사용한다. 계산식·파라미터·선정 규칙이 실제 레거시에서 유래했다는 출처 증거가 있을 때만 이 상태를 쓴다.
- 기존 RS·v_accel·final score·Gate 성과를 보고 신호 후보를 골랐거나 방향·임계값을 정한 사실은 독립 발견으로 주장하지 않는다. 이 절차는 연구자의 사전 지식을 완전히 증명할 수는 없으므로, 목록·근거·해시·시각을 남겨 사후 선택 재량을 제한한다.

### 2.1.1 자동 레거시 상관 보강 검사

- 등록표 동결 직후, 결과수익을 읽기 전에 자동 스크립트가 신규 신호와 모든 `LEGACY_CONTROL_ONLY` 값의 같은 날짜·같은 적격 모집단 내 상관을 계산한다. 최소 산출값은 일별 횡단면 Pearson 상관과 Spearman 순위상관의 중앙값·분포, 동일 `Top-K` 분위 중복률, 데이터/코드/결과물 SHA-256이다.
- 상관·중복 임계값은 라운드 시작 전에 수치로 등록한다. 임계값이 없으면 라운드 등록은 유효하지 않다. 자동 검사는 신호 발견 규칙이나 성과 판정에 입력하지 않고, 독립성 근거를 검증 가능한 기록으로 보강한다.
- 사전등록 임계값을 넘으면 상태를 `LEGACY_REDUNDANT_OR_REVIEW`로 자동 표시한다. 이 상태의 신호는 독립 추가 기여 또는 독립 후보군 승격을 주장할 수 없으며, 출처·계산식·파라미터에 대한 별도 검토가 끝날 때까지 통제군 비교로만 남긴다.
- 높은 상관은 중복의 증거일 뿐 유래의 증거가 아니다. 자동 검사는 상관만으로 `LEGACY_DERIVED`로 강등하지 않는다.
### 2.2 RESEARCH_DERIVED 파라미터 출처

- 모든 윈도우 길이·임계값·정규화·결측 처리 규칙은 `parameter_registry_id`에 기록한다.
- 허용 출처는 `MARKET_STRUCTURE`, `ACADEMIC_OR_PUBLIC_METHOD`, `PRE_REGISTERED_DESIGN`, `RAW_DATA_CONSTRAINT`뿐이다. 각 항목은 출처 설명 또는 문헌/규칙 참조를 갖는다.
- 레거시 튜닝 결과에서 가져온 값은 `LEGACY_DERIVED`로 표시하며 독립 발견용 `RESEARCH_DERIVED` 파라미터로 재사용할 수 없다. 통제군 비교에는 사용할 수 있다.
- 파라미터값을 Train 결과 뒤에 바꾸면 같은 라운드의 확증을 계속할 수 없고, 새 탐색 라운드·새 registry ID·새 코드 해시를 만든다.

## 3. 세 층의 질문과 지표

### 3.1 신호 유효성 층

질문: 신호가 같은 날짜의 종목 사이에서 이후 결과의 우열을 구분하는가?

- 레짐별 일별 Rank IC와 신뢰구간
- 신호 분위별 미래수익의 단조성
- 신호 간 상관행렬·중복성
- 동일 신호의 유효성은 Train에서만 발견하고, 선택된 방향은 고정한다.
- 신호 유효성은 진입·청산 전략 또는 운영 승격 판정이 아니다.

### 3.2 후보 선별 층

질문: 유효 신호가 실제 운용 가능한 일일 후보 묶음을 만드는가?

- 사전등록한 모집단·후보 수 상한·동일가중 규칙을 사용한다.
- 기본 기준선은 **같은 날짜·같은 적격 모집단 전체의 동일가중 비용 차감 순수익**이다. 후보 바스켓과 기준선은 같은 신호시점·진입·보유·청산·비용 계약을 사용한다.
- 주 지표: 일별 후보 바스켓의 비용 차감 순수익과 기본 기준선 대비 초과수익.
- 무작위 동일 크기 재표본은 불확실성·우연 선택 점검용 보조 기준선이고, 시가총액가중 기준선은 시장노출 민감도 점검용 보조 기준선이다. 어느 것도 라운드 후 주 기준선으로 바꿀 수 없다.
- 후보 수 상한은 성과가 아니라 연구 가상매매의 실제 처리 가능 용량으로 정한다.
- `Top-K`, 동점 처리, 후보 없음, 후보 과다일의 처리 규칙을 실행 전 고정한다.

### 3.3 전략 실행 층

질문: 후보 묶음을 특정 진입·보유·청산 구조로 운용할 수 있는가?

- 전략은 `모집단 + 상황 + 신호 + 선별 + 진입 + 보유기간 + 청산 + 동시보유/회전 제약`의 완결 가설이다.
- 각 전략군은 발견 전에 자연 보유기간과 청산 규칙을 지정한다.
- 공통 h5는 전략 간 후보 품질의 보조 비교값으로만 기록할 수 있다.
- 비용 후 수익, MDD, PF, 회전율, 용량, 체결 가능성은 이 층에서만 판정한다.

## 4. 레짐의 역할

- 레짐은 전략 스위칭의 전제가 아니라 후보 품질 차이를 설명하는 상황 변수다.
- 레짐 계산은 시점 절단 truncate-replay로 lookahead가 없음을 증명해야 한다.
- 레짐별 결과는 표본 부족을 별도 `DEFERRED_INSUFFICIENT_SAMPLE`로 남긴다.
- 레짐의 경제적 유용성은 신호·후보 규칙의 증분 설명력으로 판단하며, 정답 레짐이라는 표현은 쓰지 않는다.

## 5. 탐색과 확증

### 5.1 탐색

- Train에서 사전 제한한 독립 신호군을 3.1 → 3.2 순서로 점검한다.
- 다중 신호는 Rank IC·중복성 검증을 통과한 신호만 후보로 남긴다.
- 두 축 결합은 각 축의 단독 효과와 증분 효과가 기록된 경우에만 허용한다.
- 세 축 결합은 두 축 결합의 확증 통과 후에만 허용한다.

### 5.2 확증

- Train 탐색에서 선택한 가설·후보 수·비용·보유기간·기준선을 동결한다.
- Validation/OOS에서 수정 없이 재현한다.
- 시간 중첩이 있는 경우 purged/embargo 분할을 적용한 CPCV·PBO를 사용한다.
- 다수 전략·파라미터의 성과 평가는 DSR·Plateau·비용 민감도를 함께 기록한다.
- 통과 기준은 평균만이 아니라 최소 절대 효과, 신호일 수, 달력 기간, 비연속 에피소드, 불확실성 밴드로 사전등록한다.

### 5.3 개발 Walk-Forward와 봉인 최종 OOS

V3는 개발용 Walk-Forward와 최종 OOS를 구분한다. 개발 구간의 결과는 가설·구현의 재현성을 점검하는 근거이고, 최종 OOS는 그 뒤 한 번만 쓰는 봉인 판정 구간이다.

| 구분 | Train | Validation | 역할 |
|---|---|---|---|
| DEV-WF-1 | 2020-01-01 ~ 2021-12-31 | 2022-01-01 ~ 2022-12-31 | 개발 검증 |
| DEV-WF-2 | 2020-01-01 ~ 2022-12-31 | 2023-01-01 ~ 2023-12-31 | 개발 검증 |
| DEV-WF-3 | 2020-01-01 ~ 2023-12-31 | 2024-01-01 ~ 2024-12-31 | 개발 검증 |
| SEALED-OOS | 관측 이력 감사에서 `UNSEEN`으로 적격 판정된 완결 구간 | 해당 없음 | 최종 봉인 OOS |

- 실제 거래일 경계는 가격 계약의 전역 거래일 달력으로 결정한다. 2026년 부분 기간은 최근성 관찰용으로만 기록하고, 최종 OOS 통과·기각에는 쓰지 않는다.
- 하나의 가설은 모든 DEV-WF를 결과 공개 전 하나의 `batch_id`로 동시 등록·실행한다. 개별 개발 fold의 결과는 전체 batch 결과물 해시가 만들어질 때까지 별도로 열람·수정·재등록할 수 없다.
- `REPRODUCIBLE`은 사전등록된 모든 적용 대상 DEV-WF가 기준을 충족하고, 그 뒤에 열람한 SEALED-OOS가 기준을 충족할 때만 가능하다. 표본 부족 fold는 통과로 간주하지 않고 `DEFERRED_INSUFFICIENT_SAMPLE`으로 남긴다. 레짐 특화 가설은 적용 대상 DEV-WF/에피소드를 사전등록해야 하며, 불리한 fold를 사후 제외할 수 없다.
- `SEALED-OOS`는 특정 연도로 미리 주장하지 않는다. 라운드 동결 전에 관측 이력 감사가 완결 구간 전체를 `UNSEEN`으로 적격 판정하고, 그 감사 결과물 SHA-256을 등록표에 붙인 경우에만 배정한다. 이전 연구 결과물과 한 날짜라도 겹치면 `QUARANTINED_PRIOR_RESEARCH_ARTIFACT`로 기록하고 최종 OOS 근거로 사용하지 않는다.
- 다른 분할이 필요하면 이유·영향·새 `protocol_version`과 새 관측 이력을 사전등록한다. 기존에 관측한 날짜를 새 라운드의 Validation 또는 OOS로 되돌릴 수 없다.

### 5.4 관측 이력(Observation Ledger)

- 모든 라운드는 사용한 달력 구간별로 `round_id`, `batch_id`, 역할(`TRAIN` / `VALIDATION` / `SEALED_OOS` / `EXPLORATION_ONLY`), 최초 계산 시각, 최초 사람이 결과를 본 시각, 결과물 SHA-256, 관측 상태를 기록한다.
- 관측 상태는 `UNSEEN`, `BATCH_SEALED_NOT_VIEWED`, `OBSERVED`, `QUARANTINED_OBSERVED`, `QUARANTINED_PRIOR_RESEARCH_ARTIFACT`, `UNVERIFIED_NO_SCANNED_EVIDENCE` 중 하나다. 저장된 prior-research 결과물은 사람의 최초 열람 시각을 재구성할 수 없어도 보수적으로 `QUARANTINED_PRIOR_RESEARCH_ARTIFACT`로 둔다. `OBSERVED` 또는 `QUARANTINED_*` 날짜는 이후 새 가설의 blind Validation·SEALED OOS·확증 근거로 사용할 수 없다.
- 순차 라운드가 불가피하면 이전 fold 결과를 보고 새 라운드를 설계·등록했다는 사실과 영향 구간을 등록표에 명시한다. 그 라운드는 독립 확증이 아니라 탐색 또는 관찰 결과로만 분류한다.
## 6. 통과·보류·기각

- `SCREENED`: 신호 유효성 층에서 재현된 방향성만 확인됨.
- `CANDIDATE`: 후보 선별 층의 Train 결과가 사전등록 기준을 충족.
- `REPRODUCIBLE`: 사전등록한 모든 개발 Validation fold와 아직 관측되지 않은 SEALED OOS, 그리고 다중검정 통제를 통과.
- `PAPER_READY`: 연구 후보 생성기에서 별도 표본 축적을 시작할 수 있음.
- `DEFERRED_INSUFFICIENT_SAMPLE`: 표본 부족. 실패와 혼합하지 않음.
- `NOT_SUPPORTED`: 충분한 표본에서 기준 미달.

`REPRODUCIBLE` 전에는 기존 로직 수정·대체, Gate 변경, 주문·브로커 연결을 논의하지 않는다.

### 6.1 상태 전이 거버넌스

- `SCREENED`, `CANDIDATE`, `REPRODUCIBLE`은 등록표 SHA-256, 데이터 스냅샷 ID, 코드 해시, 실행 로그, 결과물 해시가 모두 일치할 때만 산출 스크립트가 판정한다. 사람이 과거 등록표나 결과물을 덮어써 상태를 올릴 수 없다.
- 등록표·결과물·판정은 `round_id`와 UTC/KST 생성 시각으로 연결한다. 수정은 덮어쓰기가 아니라 새 `round_id` 또는 새 버전으로 남긴다.
- `observation_ledger`는 상태 전이 증거의 일부다. SEALED OOS 완결 구간이 관측 이력 감사에서 `UNSEEN`으로 적격 판정됐고 그 결과물 해시가 등록됐다는 증거가 없으면 `REPRODUCIBLE`로 올릴 수 없다.
- `PAPER_READY`는 자동 승격이 아니다. `REPRODUCIBLE` 증거를 첨부한 별도 승인 기록과 사용자의 명시 승인이 있을 때만 연구 후보 생성기 가동 대상으로 표시한다.
- `DEFERRED_INSUFFICIENT_SAMPLE`과 `NOT_SUPPORTED`는 동일 증거 묶음 안에서 상태 전이와 별도로 남기며, 표본 추가 후 재실행해도 이전 판정을 지우지 않는다.

## 7. 라운드 시작 전 필수 등록표

각 라운드는 다음을 한 파일에 고정해야 한다.

- 질문과 층(신호 유효성 / 후보 선별 / 전략 실행)
- 모집단·데이터 스냅샷·상장/상폐 처리·유동성 제외 기준
- 입력 출처 분류와 코드 해시
- `feature_dictionary_id`·신호 후보 목록 SHA-256·동결 시각·각 신호의 경제적 근거와 `LEGACY_ADJACENCY`
- 자동 레거시 상관 보강 검사의 대상·임계값·코드 해시·결과물 경로 및 `LEGACY_REDUNDANT_OR_REVIEW` 처리 규칙
- `parameter_registry_id`·각 파라미터값·허용 출처·레거시 파생 여부
- 전략군의 완결 정의 또는 신호 정의
- 주 보유기간·진입·청산·비용
- 후보 수 상한 및 바스켓 규칙
- 기준선·조합 목록·다중검정 보정
- 최소 표본·달력 기간·비연속 에피소드
- 개발 Walk-Forward batch·SEALED OOS·Train/Validation/OOS·purge/embargo 규칙
- observation_ledger의 구간별 최초 계산/열람 시각·역할·SHA-256·관측 상태
- 기준선 기본값(동일 날짜·동일 적격 모집단·동일가중)과 보조 기준선의 역할
- `round_id`·등록표/데이터/코드/결과물 해시·상태 전이 증거·PAPER_READY 별도 승인 여부
- 운영 경로 미변경 선언

## 8. 현재 V2와의 관계

- V2의 가격·실행·시간분리·운영분리 계약은 그대로 유지한다.
- V3는 기존 로직 어휘 의존을 끊고, 신호·후보·전략 성과를 분리하는 연구 설계다.
- V3를 활성화하기 전에는 이 초안의 입력 출처·후보 수·전략군 정의를 실행 가능한 값으로 확정해야 한다.
