## 2. 『프로그래머의 뇌』 — 어디서 막히나 (헷갈림 세 종류)

### 처리 능력 부족 (작업 기억 4~7개를 넘는 곳)
- `plan_orders`: 인자 12개, 분기 26개. 한 함수가 커버리지 검사 → 정수화 → 매도 계획 → 매수 계획 → 사전 차단을 다 한다. **매 집행마다 쓰이고, 정수화가 D7(`targets.build_target_portfolio`)에 사본으로 한 번 더 있다** — 읽는 사람이 두 곳을 머리에 같이 올려야 차이를 안다
- `daily_ops.morning`: 할 일 세 종류(래치 청산·노출 변경·재주문)가 한 함수 안에서 분기
- `test_one`: 부하는 가장 크지만 09-22 한 번 쓴다 → 정리 우선순위 낮음

### 정보 부족 (필요한 정보가 화면에 없는 곳)
- 주문 ID 문자열을 **세 곳**에서 조립(`orders.py:54`, `run_execution_day.py` 시험·청산)하고, 청산은 `endswith(f"|{ymd}|1")` 로 **문자열을 해석**한다 — ID 형식을 알려면 세 파일을 봐야 한다
- `poll_until_done` 의 `query_complete=last` — 이름은 "조회가 완전", 실제 뜻은 "시간이 다 됐다"

### 지식 부족 (도메인·외부 지식이 필요한 곳)
- KIS 코드값(`sll_buy_dvsn_cd` "01"=매도/"02"=매수, `ccld_dvsn` "00"/"01")이 코드에 날값으로 흩어짐. 방향 코드표가 `execution.py:170` 과 `fills.py:18` 두 곳
- **비컨(목적 단서)은 좋은 편**: 수리 지점마다 "[날짜] 왜" 주석이 있다. 다만 주석이 길어져 코드보다 설명이 많은 함수가 생겼다(`kis_adapter.fetch_day_orders`)

### 이름 일관성
- 용어집 6.2 의 어긋남 네 개(`intent_id`, `strategy_equity`, `rebalance_phase`, `basket`) — 읽을 때마다 번역 비용
