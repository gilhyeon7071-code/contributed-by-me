# 후보 생성 검증 방법론 가드 V2

## 1. 목표

기존 로직의 매매 기록이나 현재 Gate를 정답으로 검증하지 않는다. 역사 데이터에서 그 시점의 후보 품질을 높인 조건을 찾고, 그 증거로 후보 생성 방식을 수정 또는 대체한다. 수정한 연구 후보 생성기로 새 가상매매 표본을 쌓아 재검증한 뒤에야 운영 적용 가능성을 판단한다.

기존 로직은 수정 대상일 수도 있고 유지할 일부 구성요소일 수도 있다. Gate, LOCK, 주문, 체결, 원장은 검증의 정답이나 성과 기준이 아니며 별도 운영 계약으로 유지한다.

## 2. 방법론과 무관하게 유지할 기반

- `PRICE_HISTORY_INTEGRITY_V1`과 실제 글로벌 거래일 기준 h1/h2/h5
- 신호일 종가 관측 후 다음 실제 거래일 시가 진입이라는 역사 실행 가정
- 사전 고정한 수수료와 슬리피지
- Train / Validation / OOS 시간 분리
- 연구 산출물과 운영 Gate·LOCK·주문·브로커·paper runtime의 분리

## 3. 지금까지 단일 전략 검증의 위치

돌파·평균회귀·거래량돌파·이동평균크로스·단순모멘텀 검증은 버리는 작업이 아니다. 이들은 해당 문법을 아무 상황에서나 단독 매수했을 때 비용을 견디는지를 본 통제군이다.

단일 전략의 양성 결과는 운영 승격 근거가 아니며, 음성 결과를 보고 임계값·Top-N·기간·보조 신호를 사후 조정하지 않는다. 단일 전략을 계속 추가 검증해 방법론 탐색을 대체하지 않는다.

전략 문법에 순위 또는 선택 조건이 이미 있으면 그대로 사용한다. 없으면 임의의 Top-N, RS, 거래량 등 보조 조건을 붙이지 않고 전체 신호를 검증한다.

## 4. 검증 축

다음 축은 모두 필수 AND 조건이 아니다. 각 축의 단독 효과와 추가 기여를 분리해 검증한다.

1. 상황: 시장, 변동성, 유동성, 섹터, 이벤트 등
2. 후보군: 해당 시점에 탐색할 종목 집합
3. 전략 문법: 추세, 돌파, 평균회귀, 모멘텀 등 가격 행동 해석
4. 신호: 상대강도, 거래량 가속, 수급, 뉴스 등 개별 근거

## 5. 탐색 라운드와 확증 라운드

### 5.1 탐색 라운드

사전에 제한한 가설군과 조합 목록 안에서 후보 조건을 발견한다. 탐색 결과는 운영 승격·정책 변경·성공 판정에 사용하지 않는다. 탐색에서 남긴 가설은 다음 확증 라운드 전에 동결한다.

### 5.2 확증 라운드

동결한 조합, 주 지표, 최소 표본, 시간 분할, 비용, 실행 가정으로 Validation/OOS에서만 판정한다. 탐색 결과를 보고 조합·지표·임계값·기간을 바꾸면 새 탐색 라운드로 분리한다.

## 6. 탐색 시작 전 사전 등록

아래 항목을 문서와 실행계획에 수치 또는 명시적 규칙으로 고정하기 전에는 확증 탐색을 시작하지 않는다.

### 6.1 모집단과 후보 품질 주 지표

- 대상 시장, 상장·유동성·가격·거래대금 제외 규칙, 데이터 스냅샷을 고정한다.
- 주 지표는 거래별 평균이 아니라 **신호일별 동일가중 후보 바스켓의 비용 차감 순수익**으로 정의한다. 후보가 많이 나온 날이 과대 반영되지 않게 한다.
- 주 보유기간은 실제 의도한 운용 보유기간으로 하나만 고정한다. h1/h2/h5 중 어느 것이 주 지표인지 현재 또는 과거 결과를 보고 선택하지 않는다.
- 중앙값, 승률, 손익분포, 거래별 수익, 다른 보유기간은 보조 진단으로 기록하되 단독 통과 판정에 사용하지 않는다.
- 일별 후보 바스켓의 구성 방식과 최대 후보 수·자본배분 가정도 사전에 고정한다.

### 6.2 검증 조합 목록

검증할 축, 축별 값, 조합, 기준선, 비교 대상 목록을 라운드 시작 전에 기록한다. 탐색 중 조합 추가는 금지하며, 추가가 필요하면 다음 탐색 라운드로 넘긴다.

### 6.3 다중비교 통제

- 일별 후보 바스켓 수익률 시계열을 검정 단위로 사용한다.
- 시간 의존과 보유기간 중첩이 있으면 purged / embargo 분할을 적용한 CPCV와 PBO를 사용한다.
- Deflated Sharpe Ratio는 다수 시도에 따른 과대 성과 가능성을 보는 보조 통계로 사용한다. CPCV/PBO의 대체물이 아니다.
- 적용 통계, purge/embargo 길이, 조합 수, 통과 기준을 사전에 고정한다.

### 6.4 셀 최소 표본

셀 표본은 거래 행 수가 아니라 고유 신호일 수를 기준으로 한다. 각 Train/Validation/OOS와 필요한 세부 셀에 대해 최소 고유 신호일 수, 최소 달력 기간, 최소 비연속 구간 수를 사전에 고정한다. 기준 미달은 통과·기각이 아니라 `DEFERRED_INSUFFICIENT_SAMPLE`이다.

### 6.5 축 추가와 상호작용

주문 효과를 피하기 위해 아래 계층을 고정한다.

1. 단일 축의 주 지표 효과
2. 사전 등록한 두 축 결합의 증분 효과
3. 두 축 결합이 확증을 통과한 경우에만 사전 등록한 세 번째 축의 증분 효과

세 축 이상에서는 임의의 순서 비교 대신 이 계층을 사용한다. 필요하면 동일 조합에 대해 기준 축을 바꾼 대칭 비교도 기록하되, 새 조합 탐색으로 취급한다.

### 6.6 상황 축 lookahead 점검

상황 라벨은 그 시점까지 알 수 있는 데이터만으로 재현 가능해야 한다. 전기간 학습 HMM 등 미래 정보를 쓰는 분류는 금지한다. 각 `as_of` 시점에서 데이터를 절단해 다시 계산해도 해당 시점 이전 라벨이 동일한지 truncate-replay 회귀 검증을 수행한다.

## 7. 허용되는 검증 순서

1. 상황만으로 후보 품질이 달라지는지 확인한다.
2. 후보군, 전략 문법, 신호의 단독 효과를 확인한다.
3. 사전 등록한 두 축 결합이 실제 증분 효과를 만드는지 확인한다.
4. 통과한 두 축 결합에 한해 세 번째 축이 개선인지 과적합인지 확인한다.
5. 확증을 통과한 후보 생성 규칙만 다음 시가·비용·체결 가능성 검증으로 보낸다.
6. 역사 검증과 새 paper 표본이 함께 지지할 때 기존 로직의 일부 수정 또는 대체 여부를 판단한다.

## 8. 연구 후보 생성기와 paper 표본

### 8.1 가동 규칙

연구 후보 생성기는 확증을 통과한 조건만 사용한다. 가동 전에 최소 가상매매 고유 신호일 수, 최소 기간, 목표 레짐 또는 범용성 요구를 고정한다.

- 범용 조건은 서로 다른 레짐에서의 재현을 요구한다.
- 레짐 특화 조건은 서로 다른 레짐 수가 아니라 **목표 레짐의 비연속 에피소드 두 개 이상**에서의 재현을 요구한다.
- 조건을 수정하면 생성기 버전을 올리고 이전 표본과 섞지 않는다.

각 후보 표본에는 최소한 `generator_version`, `selection_rule_id`, `validation_protocol_version`, `price_data_snapshot_id`, `code_hash`, `as_of`, `regime_label`을 기록한다.

### 8.2 역사와 paper의 함께 지지 판정

방향 일치만으로 지지하지 않는다. 사전에 정한 최소 절대 효과, 표본 기준, 불확실성 밴드 또는 신뢰구간을 함께 적용한다. 역사 효과가 충분히 큰 경우에만 사전 등록한 허용 감쇠폭을 추가로 적용한다. 효과가 0에 가까울 때 감쇠율만으로 판정하지 않는다.

역사는 지지하지만 paper가 기준을 충족하지 못하면 기각이 기본이다. 표본 부족이면 `DEFERRED_INSUFFICIENT_SAMPLE`으로 분리한다.

## 9. 일부 수정·대체·롤백

- 새 조건이 기존 Gate 통과 후보 위에서도 사전 등록한 증분 효과를 보이면 필터 추가 후보로 본다.
- 새 조건이 존재할 때 기존 Gate 구성요소의 증분 효과가 0 이하로 재현되면 대체 후보로 본다.
- 어느 경우에도 운영 반영은 별도 승인 절차를 거친다.
- 적용 승인 시 모니터링 기간, 주 지표 하한 밴드, 롤백 트리거, 재검증 주기를 함께 고정한다.
- 재검증에서 기여가 소멸하면 롤백 절차를 따른다.

## 10. 사용자 의견과 방향 변경 판단

사용자의 생각·의문·예시는 자동 수정 지시가 아니다. 목표, 데이터·시간 분리·실행 계약, 검증 근거, 과적합·운영 부작용을 독립적으로 판단한다. 판정은 `반영`, `부분 반영`, `미반영` 중 하나와 근거를 짧게 기록한다.

## 11. 금지되는 진행

- 기존 운영 로직을 검증의 정답으로 두기
- 상황·후보군·전략·신호를 모두 만족해야만 후보가 된다고 가정하기
- 탐색 결과를 보고 확증 지표·조합·임계값·기간을 바꾸기
- 단일 전략 검증을 끝없이 추가해 방법론 탐색을 대체하기
- 연구 결과를 근거 없이 Gate, LOCK, 주문, 브로커, paper runtime에 반영하기

## 12. 매 검증 시작 전 체크리스트

- 이 가드를 읽었는가
- 현재 고정 목표와 이번 검증 질문을 한 문장으로 썼는가
- 탐색 라운드인지 확증 라운드인지 선언했는가
- 모집단, 데이터 스냅샷, 주 지표, 주 보유기간, 후보 바스켓 구성을 고정했는가
- 검증 축·조합·기준선·다중비교 통제를 사전 등록했는가
- 셀 최소 고유 신호일 수와 `DEFERRED_INSUFFICIENT_SAMPLE` 처리를 고정했는가
- 레짐 lookahead truncate-replay 검증 여부를 선언했는가
- 운영 경로 미변경을 명시했는가

시작 보고에는 `가드 읽음`, `현재 고정 목표`, `탐색/확증 라운드`, `방향 변경 여부`, `이번 검증 범위`를 반드시 포함한다. 범위를 바꿀 필요가 생기면 실행 전에 근거와 영향 범위를 기록한다.
