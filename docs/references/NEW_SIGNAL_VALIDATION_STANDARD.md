# 새 신호 검정 기준서

- 제정: 2026-08-24
- 적용 범위: **연구 목적의 모든 측정 라운드** (2026-08-31 v1.1 확대).
  RootA 새 후보 생성 신호·후보 선별 규칙·보유기간 가설에 더해,
  기존 결과의 재측정, 재현 시도, 기준선 교체 대조, 축(axis) 탐색, 전략 대 대안 비교를 포함한다.
  **운영 배관 수리와 결함 진단은 이 기준서의 대상이 아니다**(측정이 아니라 수리다).
  강제 도구: `tools/round_preflight.py` (--new / --freeze / --check)
- 운영 영향: 없음. 이 문서는 Gate, LOCK, 주문, 체결, 원장, 브로커, paper runtime을 변경하지 않는다.
- 선행 기준: `STRATEGY_VALIDATION_GUARD.md`, `METRIC_CITATION_PROTOCOL.md`

## 1. 현재 고정 목표

현재 목표는 v41.1 신호를 보수하거나 임계값만 조정하는 것이 아니다.

목표는 다음 두 가지를 분리하는 것이다.

1. 기존 주문-체결-원장-대시보드 배관은 유지한다.
2. 새 매수 신호는 역사 패널에서 사전등록 검정을 통과한 경우에만 연구 후보 생성기로 올린다.

현재 v41.1 관련 관측에서 나온 `중간 거래대금`, `중간 v_accel`, `중간 ATR`, `다일 보유` 같은 방향은 가설 후보일 뿐이다. 사후 관측 결과를 운영 신호 근거로 사용하지 않는다.

## 2. 금지 판단

아래는 새 신호 검정에서 금지한다.

- 기존 Gate 통과 여부를 정답으로 두기
- 기존 v41.1 매매 결과를 새 신호의 학습 라벨로 쓰기
- 결과를 본 뒤 보유기간, 임계값, 후보 수, 기준선을 바꾸기
- 거래별 평균 수익만으로 통과 판정하기
- 후보가 많이 나온 날을 과대 반영하기
- 표본 부족을 성공 또는 실패로 포장하기
- 연구 결과를 근거 없이 Gate, LOCK, 주문, 브로커, paper runtime에 반영하기

## 3. 라운드 종류

### 3.1 탐색 라운드

목적은 후보 가설을 좁히는 것이다.

탐색 라운드 결과는 운영 적용, 정책 변경, 자본 확대, Gate 변경의 근거가 아니다. 탐색에서 살아남은 가설은 다음 확증 라운드 시작 전에 동결한다.

### 3.2 확증 라운드

목적은 동결된 가설이 Validation과 OOS에서 재현되는지 보는 것이다.

확증 라운드 중 조합, 임계값, 주 지표, 보유기간, 표본 기준을 바꾸면 그 라운드는 즉시 탐색 라운드로 강등한다.

### 3.3 탐색과 확증은 데이터 구간을 분리한다

가설을 동결해도 **같은 데이터로 확증하면 out-of-sample이 아니다.** 동결은 조건을 고정할 뿐,
그 조건이 어느 구간을 보고 나왔는지를 지우지 못한다.

확증은 아래 둘 중 하나로만 한다.

- **(가) 구간 분할** — 탐색은 Train 구간만 사용한다. 탐색 중 Validation/OOS 구간 열람을 금지한다.
- **(나) 전진 관측** — 확증은 사전등록일 이후에 생성된 데이터로만 한다.

**2026-08-24 이전의 전 구간(2015-01-02 ~ 2026-08-21)은 이미 열람됐다.**
그 구간을 사용하는 확증 라운드는 `REPRODUCIBLE_RESEARCH_ONLY` 이상으로 올릴 수 없다.
이 사실을 지우고 "과거 데이터로 확증했다"고 기록하는 것을 금지한다.

## 4. 사전등록표

검정을 시작하기 전에 아래 항목을 한 문서에 고정한다.

| 항목 | 필수 기재 |
|---|---|
| `round_id` | 예: `NSV_YYYYMMDD_001` |
| `protocol_version` | 이 문서 버전 또는 후속 개정 버전 |
| 검정 질문 | 한 문장. 예: "중간 v_accel 구간은 동일 모집단 기준선보다 h5 초과수익이 양수인가" |
| 라운드 종류 | `EXPLORATION` 또는 `CONFIRMATION` |
| 모집단 | 시장, 상장일, 가격, 거래대금, 거래정지, 관리종목, 데이터 결측 제외 규칙 |
| 데이터 스냅샷 | 가격 패널, 재무, 뉴스, 수급 등 파일 경로와 SHA-256 |
| 가설 목록 | 축, 값, 조합, 임계값, 후보 수 상한 |
| 기준선 | 같은 날짜, 같은 적격 모집단, 같은 진입/보유/청산/비용 계약 |
| 주 지표 | 신호일별 동일가중 후보 바스켓의 비용 차감 초과수익 |
| 주 보유기간 | h1/h2/h5/h10 중 하나만 주 지표로 고정 |
| 보조 지표 | 승률, 중앙값, 손익분포, MDD, 거래별 수익, 다른 보유기간 |
| 비용 | 수수료, 세금, 슬리피지, 진입/청산 가격 가정 |
| 시간 분할 | Train, Validation, OOS, purge/embargo 규칙 |
| 최소 표본 | 고유 신호일 수, 달력 기간, 비연속 구간 수 |
| `MDE` | 사전등록 표본에서 검정력 80%로 검출 가능한 최소 효과크기. **계산 과정과 사용한 분산 추정치를 함께 적는다** |
| `MES` | 최소 의미 효과크기. 비용 차감 후 이보다 작으면 통과여도 운영 의미가 없다. **비용 계약을 근거로 정한다** |
| 검정 조합 수 | 이 라운드에서 시도할 조합의 총 개수. 사전에 고정한다 |
| 다중비교 통제 | 검정 조합 수가 3을 넘으면 보정을 **필수**로 한다(CPCV/PBO 또는 등가). 3 이하일 때만 미적용 사유 기재로 갈음할 수 있다 |
| 실패 기준 | 어떤 결과면 `NOT_SUPPORTED`인지 |
| 보류 기준 | 어떤 결과면 `DEFERRED_INSUFFICIENT_SAMPLE`인지 |
| 운영 분리 선언 | 운영 Gate, LOCK, 주문, 브로커, paper runtime 미변경 |

### 4.1 시작 금지 규칙

**`MDE > MES` 이면 그 라운드를 시작하지 않는다.**

이 표본으로 검출할 수 있는 최소 효과가 운영상 의미 있는 최소 효과보다 크다는 뜻이고,
그 경우 결과는 시작 전에 이미 정해져 있다 — 효과가 있어도 못 보고 `DEFERRED`로 끝난다.
표본을 더 모으거나, 질문을 바꾸거나, 보유기간을 늘려 분산을 낮추는 것이 순서다.

**이 규칙이 없으면 최소 표본만 정하고 시작하게 되고, 그것이 이전 방법론 세 벌이
모든 라운드를 `DEFERRED_INSUFFICIENT_SAMPLE`로 끝낸 이유다. 미리 알 수 있는 결과였다.**

## 5. 주 지표

주 지표는 거래별 평균이 아니라 **신호일별 동일가중 후보 바스켓의 비용 차감 초과수익**이다.

정의:

```text
daily_candidate_return[D] = D일 후보들의 동일가중 비용 차감 수익률
daily_baseline_return[D] = 같은 D일 적격 모집단 전체의 동일가중 비용 차감 수익률
daily_excess_return[D] = daily_candidate_return[D] - daily_baseline_return[D]
primary_metric = mean(daily_excess_return) over eligible signal days
```

후보가 없는 날은 주 지표 평균에 넣지 않는다. 단, 후보 발생일 비율과 후보 공백 기간은 별도 보조 지표로 반드시 기록한다.

### 5.1 후보 발생일 선택편향 점검 (필수 보조 지표)

후보가 나오는 날 자체가 특정 시장 상황일 수 있다. 그러면 주 지표는 신호의 힘이 아니라
**"어떤 날에 거래하는가"의 효과**를 재게 된다.

각 라운드는 아래를 반드시 함께 기록한다.

```text
후보 발생일의 시장 수익 분포   vs   비발생일의 시장 수익 분포
후보 발생일 비율               (예: 1,653 / 2,836일 = 58%)
```

두 분포가 유의하게 다르면 그 사실을 `decision.md`에 명시하고, 주 지표를 단독 근거로 쓰지 않는다.

## 6. 기본 통과 기준

라운드별로 더 강한 기준을 사전등록할 수 있다. 더 약하게 바꾸려면 별도 승인과 새 `protocol_version`이 필요하다.

### 6.1 Train

Train은 발견 구간이다. Train 단독으로 통과, 운영 적용, 자본 확대를 말하지 않는다.

Train에서 최소 조건:

- 주 지표가 **비용 차감 후 사전등록한 MES 를 넘어야 한다** (0 초과가 아니라 MES 초과).
- 비용 차감 후에도 양수여야 한다.
- 후보 발생일이 최소 표본 기준을 충족해야 한다.
- 효과가 한두 날짜의 극단 수익에만 의존하지 않아야 한다.

### 6.2 Validation

Validation 통과 조건:

- 주 지표가 **비용 차감 후 사전등록한 MES 를 넘어야 한다** (0 초과가 아니라 MES 초과).
- 신뢰구간 또는 불확실성 밴드가 0을 지나면 `WEAK_SUPPORT` 이하로 둔다.
- 연도 또는 fold 대부분에서 방향이 같아야 한다.
- Train 대비 효과 감쇠가 사전등록 허용 범위 안이어야 한다.

### 6.3 OOS

OOS 통과 조건:

- Validation과 같은 방향이어야 한다.
- 주 지표가 **비용 차감 후 사전등록한 MES 를 넘어야 한다** (0 초과가 아니라 MES 초과).
- 최소 고유 신호일, 최소 달력 기간, 최소 비연속 구간 수를 모두 충족해야 한다.
- OOS를 본 뒤 어떠한 임계값도 바꾸지 않아야 한다.

OOS가 표본 부족이면 `DEFERRED_INSUFFICIENT_SAMPLE`이며, 통과가 아니다.

## 7. 기본 실패 기준

아래 중 하나면 해당 라운드는 `NOT_SUPPORTED`다.

- 주 지표가 비용 차감 후 0 이하
- 기준선보다 후보 바스켓이 일관되게 열위
- 효과가 특정 한 해 또는 한 사건에만 의존
- 후보 수가 지나치게 적어 실제 운용 후보군을 만들 수 없음
- Validation 또는 OOS에서 방향이 반전
- 결과 확인 후 임계값, 보유기간, 조합을 바꿈
- 데이터 시점상 미래 정보를 사용

### 7.1 0 과 MES 사이

주 지표가 0보다 크지만 `MES` 에 못 미치면 실패도 통과도 아니다. `WEAK_SUPPORT` 로 둔다.
**"양수가 나왔다"를 통과로 읽는 것을 금지한다** — 비용 차감 후 +0.05%p 는 운영 의미가 없다.

## 8. 표본 부족 기준

아래는 실패가 아니라 `DEFERRED_INSUFFICIENT_SAMPLE`로 둔다.

- 고유 신호일 수가 사전등록 기준 미만
- 달력 기간이 사전등록 기준 미만
- 레짐 특화 가설에서 목표 레짐의 비연속 에피소드가 부족
- 후보 발생이 특정 며칠에 몰려 일별 바스켓 검정이 불안정

표본 부족은 운영 적용 근거가 아니다. 표본이 쌓이면 같은 등록 조건으로 재검정한다.

## 9. 축 검정 순서

새 신호는 아래 순서로만 올린다.

1. 단일 축 효과: 예측 방향, 기준선 대비 초과수익, 표본 안정성 확인
2. 두 축 결합: 사전등록 조합만 확인
3. 세 번째 축: 두 축 결합이 통과한 경우에만 증분 효과 확인
4. 후보 생성 규칙: 주 지표와 후보 수 상한을 함께 고정
5. 실행 검정: 다음 시가 진입, 비용, 보유기간, 청산 가정 확인
6. 연구 후보 생성기: 확증 통과 후 별도 버전으로 paper 표본 적재

세 축 이상을 한 번에 조합해 좋은 결과만 고르는 것은 금지한다.

## 10. 보유기간 기준

보유기간은 결과를 보고 선택하지 않는다.

각 라운드는 주 보유기간 하나를 사전등록한다. 다른 보유기간은 보조 진단으로만 기록한다.

다일 보유 신호를 검정한다면 청산 가정도 함께 고정한다.

- 진입: 신호일 종가 관측 후 다음 실제 거래일 시가
- 기본 청산: 사전등록한 hN 종가 또는 다음 실제 거래일 기준 가격
- 손절/트레일링: 검정 질문에 포함할 때만 사용
- 당일왕복: 별도 전략으로 분리

## 11. 레짐과 상황 라벨

레짐 라벨은 해당 시점까지 알 수 있는 데이터만으로 계산되어야 한다.

전기간을 보고 만든 라벨, 미래 데이터를 포함한 HMM, 사후 분류 레짐은 확증 근거로 쓰지 않는다.

레짐별 결과를 인용할 때는 다음을 붙인다.

- 라벨 계산식
- `as_of`별 truncate-replay 검증 여부
- 레짐별 고유 신호일 수
- 목표 레짐인지 보조 진단인지

## 12. 산출물 요구

각 라운드는 최소한 아래 산출물을 남긴다.

```text
docs/research/new_signal/<round_id>/registration.md
docs/research/new_signal/<round_id>/feature_dictionary.csv
docs/research/new_signal/<round_id>/data_snapshot_manifest.json
docs/research/new_signal/<round_id>/results_train.csv
docs/research/new_signal/<round_id>/results_validation.csv
docs/research/new_signal/<round_id>/results_oos.csv
docs/research/new_signal/<round_id>/decision.md
```

`decision.md`에는 **사전등록한 `MDE`·`MES`와 실측 주 지표를 나란히 적고**, 아래 중 하나만 쓴다.

- `EXPLORATION_CANDIDATE`
- `WEAK_SUPPORT`
- `REPRODUCIBLE_RESEARCH_ONLY`
- `DEFERRED_INSUFFICIENT_SAMPLE`
- `NOT_SUPPORTED`
- `INVALIDATED_BY_LEAKAGE`

`REPRODUCIBLE_RESEARCH_ONLY`도 운영 적용이 아니다. 운영 반영은 별도 승인 절차다.

## 13. 운영 반영 전 조건

운영 반영 논의는 아래를 모두 충족한 뒤에만 가능하다.

1. 확증 라운드 Validation/OOS 통과
2. 데이터 누수 점검 통과
3. 다중비교 통제 결과 첨부
4. 최소 paper 고유 신호일 수 사전등록
5. 연구 후보 생성기 버전, 코드 해시, 데이터 스냅샷 기록
6. 롤백 기준과 모니터링 지표 사전등록
7. 사용자 명시 승인

이 조건 전에는 Gate, LOCK, 주문, 브로커, paper runtime을 변경하지 않는다.


## 15. 현재 결론

이 기준서 작성 시점의 결론은 다음과 같다.

- 기존 v41.1 신호는 새 검정의 기준선이나 정답이 아니다.
- 기존 배관은 새 신호를 얹을 운영 자산으로 보존한다.
- 새 신호 후보는 사후 관측 기록일 뿐이며, 사전등록 검정 전에는 근거가 아니다.
- 가장 먼저 필요한 것은 새 매수 조건 적용이 아니라 검정 실패 기준의 고정이다.

### 15.1 이 기준서 작성 시점의 운영 상태

"운영 영향: 없음"은 이 문서가 운영을 바꾸지 않는다는 뜻이지, 운영이 정상 가동 중이라는 뜻이 아니다.
나중에 읽는 사람이 오해하지 않도록 당시 상태를 적어 둔다.

```
2026-08-24 기준
  v41.1 진입   장중 하드 블록 상태(09:47~). 신규 진입 없음
               신호 교체 방침에 따라 진입 정지가 검토되고 있다
  보유 포지션   005690 1주 (08-21 진입)
  배치         최근 4거래일 중 3일 실패. 후보가 2026-08-20 에 멈춰 있다
```
**즉 이 검정은 v41.1 이 정상 가동되는 상태와 병행되는 것이 아니다.**
