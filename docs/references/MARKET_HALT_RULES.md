# 시장 중단 제도와 우리 구현의 차이

2026-09-12 작성. 사용자가 제공한 조문(찾기쉬운 생활법령정보)과 실측을 나란히 둔다.

이 문서의 목적은 **결정에 쓸 재료를 한 곳에 두는 것**이다.
지금 우리 구현은 제도를 따르지 않고 자체 프록시를 쓴다. 어느 쪽으로 갈지는 열린 결정이다.

---

## 제도

### 사이드카 (프로그램매매호가 효력정지)

```
발동   선물 가격이 전일 종가 대비 일정 비율 변동한 상태가 **1분간 지속**
       KOSPI   코스피200 **선물** ±5%
       KOSDAQ  코스닥150 **선물** ±6%  **그리고** 코스닥150 **지수** ±3% 같은 방향
조치   발동 시점부터 **5분간 프로그램매매 호가 효력 정지**
해제   5분 후 자동. 단 장 종료 40분 전이 먼저 오거나,
       서킷브레이커로 중단 후 재개되면 그 시점에 해제
횟수   시장별 하루 1회
시간   정규장 개시 5분 후 ~ 장 종료 40분 전(14:50)
```

**적용 범위가 핵심이다.** 프로그램매매 호가만 제한된다.
**일반 투자자의 매수·매도 주문은 정상 진행된다.**

### 서킷브레이커 (매매거래 중단)

```
발동   지수가 전일 대비 일정 비율 하락한 상태가 **1분간 지속**
  1단계  -8%                                    -> 20분 중단 후 재개
  2단계  -15% **및** 1단계 시점 대비 1% 추가하락  -> 20분 중단 후 재개
  3단계  -20% **및** 2단계 시점 대비 1% 추가하락  -> **당일 장 종료**
재개   20분 중단 -> **10분 단일가 매매** -> 정상 거래
```
2·3단계는 하락 조건과 추가하락 조건이 **동시에** 충족돼야 한다.

## 우리 구현 (2026-09-12 실측)

```
탐지   tools/market_anomaly_detector.py   루프 Step 0, 매 사이클
입력   2_Logs/kis_ws_index_latest.json    지수 WS 틱 (0001 코스피 / 1001 코스닥 / 2001 코스피200)
판정   change_pct <= -5.0%  -> CIRCUIT_BREAKER      (레벨 HIGH)
       change_pct >= +5.0%  -> BOOST
산출   2_Logs/market_event_gate_latest.json
소비   paper_engine/entry.py:1461  market_wide 면 max_new=0
```

## 차이 — 표

| | 제도 | 우리 |
|---|---|---|
| 사이드카 대상 | 코스피200 **선물** / 코스닥150 선물+지수 | 지수 **현물** ±5% |
| 사이드카 조치 | 프로그램매매 호가만 5분 | (해당 없음 — 2026-09-12 차단목록에서 제거) |
| CB 1단계 | 지수 **-8%**, **1분 지속** | 지수 -5%, **한 틱 즉시** |
| CB 2·3단계 | -15% / -20% + 추가하락 1% | 단계 구분 **없음** |
| 중단 지속 | 20분 + 단일가 10분 | **지속시간 개념 없음.** 레벨이 올라오면 즉시 해제 |
| 3단계 | 당일 종료 | 없음 |
| 발동 창 | 사이드카 09:05~14:50 | 시간 제약 없음 |
| 횟수 | 시장별 하루 1회 | 무제한 재발동 |

## 사이드카는 왜 우리 차단 사유가 아닌가 (2026-09-12 처분)

조문: *"프로그램 매매 호가만 제한되며 일반 투자자의 매수·매도 주문은 정상적으로 진행됩니다."*

우리 발주가 프로그램매매에 해당하는가 — **실측으로 아니다.**
비차익 프로그램매매 기준은 15종목 이상 일괄인데,

```
2026-09-11  제출원장 143행   **분당 최대 4종목**
2026-09-07  제출원장 102행   분당 최대 6종목
max_new     4(19회) / 15(6회)   15는 상한이고 실제 발주는 그 아래
```

따라서 SIDECAR 를 차단 사유로 두면 **시장은 도는데 우리만 서는** 틀린 차단이 된다.
`block_event_types` / `market_wide_event_types` 에서 제거했다.
지금은 탐지기가 그 타입을 생산하지 않아 동작 변화는 0이다 —
**나중에 누가 사이드카를 구현할 때 전면 차단으로 잘못 배선되는 것을 막는 조치다.**

시험 `tests/test_market_event_observation_fail_closed.py::test_sidecar_is_not_a_block_reason`.

**조건부 재검토 트리거**: 한 번에 15종목 이상 발주하게 되면 프로그램매매 분류가 달라질 수 있다.
`max_new` 상한이 15이므로 구조적으로 가능하다.

## 열린 결정 두 개

### A. 임계값을 제도에 맞출 것인가

```
지금  지수 현물 -5% 즉시        보수적 프록시. CB 보다 먼저 걸린다
제도  지수 -8% 1분 지속
```
제도에 맞추면 **-5% ~ -8% 구간에서 매매를 허용**하게 된다 — 위험 노출이 늘어난다.
지금 프록시는 그 띠에서 **시장은 정상인데 우리만 선다**.
어느 쪽이 맞는지는 "그 띠에서 매매하고 싶은가" 에 달렸다.

### B. 지속시간을 구현할 것인가

지금은 레벨 기반이라 지수가 임계 위로 올라오는 즉시 해제된다.
제도는 시간 기반이다(20분 + 단일가 10분, 3단계는 당일 종료).

**우연히 덮인 부분이 있다**: CB 로 실제 중단되면 틱이 안 들어오고,
`MAX_SOURCE_AGE_SEC=300` 을 넘기면 관측 실패로 넘어가 2026-09-12 의 fail-closed 가 차단을 유지한다.
**의도한 설계가 아니라 부작용이다.** 재개 시각을 우리가 아는 게 아니다.

## 같이 봐야 할 것 — 단일가 구간

CB 재개 직후 **10분은 단일가 매매**다. 주문을 모아 한 가격에 체결한다.
우리 집행 가정(지정가 즉시체결·호가 기반 LOB 판정)은 그 동안 성립하지 않는다.

**실측: 단일가 처리는 코드 어디에도 없다.**
`paper_engine/` 과 `tools/kis_order_dispatch_from_exec.py` 에 `단일가`/`single_price`/`call_auction`
참조 0건 (close_auction 은 종가 단일가라 별개다).

장 시작 단일가(08:30~09:00)와 종가 단일가(15:20~15:30)도 같은 문제를 갖는다.
