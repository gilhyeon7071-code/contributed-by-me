## 1. 뼈대가 기대하는 집행 층

```
E1 주문 = 목표 − 보유  ->  E2 의도 → 준비 → 제출 → 부분·전량 체결 → 취소 → 재시도  ->  E3 체결(주문 ID 로 귀속)
```

## 2. v41.1 실제 흐름 (코드 + 산출물로 확인)

`intraday_paper_loop.py` 문서문자열(1~12행)과 2750~2783행:

```
paper_engine      후보 판단 + 수량 결정 + **가상 체결을 fills.csv 에 바로 기록**
  ↓
build_intraday_orders_exec_from_fills.py   **체결 기록으로부터** orders_D_exec.xlsx 를 만든다
  ↓
kis_order_dispatch_from_exec.py            그 주문 파일을 브로커로 보낸다 (mock + apply 이면)
  ↓                                         단 페이퍼가 이미 체결한 BUY 는 SKIP_ALREADY_PAPER_FILLED
kis_sync_fills                              브로커 체결 동기화
```

**뼈대와 순서가 반대예요. 체결이 주문보다 먼저 있어요.**
페이퍼 엔진이 판단자이면서 동시에 집행자이고, 주문 파일은 체결의 사후 기록이에요.
