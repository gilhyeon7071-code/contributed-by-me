# 주식로직 검증 진행 프롬프트

## 목적

이 프롬프트는 주식 자동매매 로직을 수익률만으로 판단하지 않고, 운영 증거 기반으로 검증하기 위한 기준이다.

검증 단위는 파일 하나가 아니라 하나의 운영 실행 단위다.

```text
run_id
-> 입력 파일
-> 후보 생성
-> orders
-> fills
-> ledger
-> stats
-> risk / freshness 로그
-> 평가표 판정
```

## 기본 원칙

- 수정하지 않는다.
- read-only로 검증한다.
- 사실은 코드, 로그, JSON, CSV, Parquet, 명령 출력으로 확인된 것만 사용한다.
- 증거가 없으면 `모름` 또는 `NA`로 판단한다.
- 추정으로 `PASS`를 주지 않는다.
- 점수 평가 전에 하드 FAIL 조건을 먼저 확인한다.
- 수익률보다 재현성, 데이터 정합성, 리스크 차단, 원인 추적성을 우선한다.
- 평가 기준은 `E:\1_Data\docs\my_trading_logic_acceptance_criteria.md`를 따른다.

## 검증 대상

가능하면 아래 자료를 확인한다.

```text
1. 후보 종목 생성 로그
2. orders 파일 또는 생성 로그
3. fills 파일 또는 체결 로그
4. ledger 반영 결과
5. stats / live_vs_paper / live_vs_bt 결과
6. freshness 체크 결과
7. redteam 체크 결과
8. risk_off / kill_switch 상태
9. 백테스트 결과
10. 실거래 또는 가상매매 결과
11. 관련 코드와 설정 파일
```

자료가 없으면 해당 항목은 `NA` 또는 `모름`으로 처리한다.

## 검증 순서

### 1. D 기준일 확정

- D는 `fills.csv`에서 최신 `BUY` ymd로 판단한다.
- `BUY`가 없으면 `datetime` 앞 8자리 기준 최신 ymd를 사용한다.
- D 산출 근거 파일과 핵심 값을 보고한다.

### 2. 하드 FAIL 선확인

아래 중 하나라도 확인되면 총점과 관계없이 `FAIL`로 판단한다.

- `orders_exec` 없음
- `exec_date != D`
- `as_of` / `run_id` 불일치
- `paper` / `broker` 날짜 혼용
- freshness HARD_FAIL 상태에서 주문 가능
- risk_off 상태에서 주문 가능
- 주문, 체결, 장부, 통계 연결 불일치
- 실행 결과 재현 불가
- 검증 실패를 무시하고 다음 단계 진행

### 3. SSOT 체인 검증

아래 흐름이 같은 D, as_of, run_id 기준으로 이어지는지 확인한다.

```text
orders(D) -> fills(D) -> ledger -> stats
```

확인할 것:

- orders 기준일
- fills 기준일
- ledger 반영 기준
- stats 반영 기준
- run_id 연결 여부
- as_of 연결 여부
- 파일 생성시각 또는 갱신시각

### 4. 재현성 검증

같은 입력, 같은 기준일, 같은 설정에서 결과가 흔들리지 않는지 확인한다.

확인할 것:

- 후보 목록 재현 여부
- 주문 목록 재현 여부
- 체결 반영 재현 여부
- stats 결과 재현 여부
- diff 또는 hash 비교 가능 여부

단독 실행이 막히는 환경이면 공식 배치 경로로 대체 검증하고 제약을 명시한다.

### 5. 정량 분석

수익률 하나만 보지 않고 아래 항목을 함께 본다.

- 수익률
- MDD
- 승률
- 손익비
- 슬리피지
- 체결률
- 미체결률
- live vs paper 차이
- paper vs backtest 차이

증거가 없으면 수익성 항목은 `NA`로 둔다.

### 6. 정성 분석

코드와 로그가 로직의 행동을 설명하는지 확인한다.

확인할 것:

- 왜 매수했는가
- 왜 매도했는가
- 왜 쉬었는가
- 왜 제외했는가
- 리스크 게이트 의미가 유지되는가
- 예외 상황에서 FAIL-CLOSED 되는가
- 정책 변경과 버그 수정이 섞이지 않았는가

### 7. 증거 추적

각 판단에는 증거 경로와 핵심 값을 붙인다.

필수 기록:

- evidence path
- run_id
- as_of
- D
- exec_date
- 파일 생성시각 또는 갱신시각
- 필요 시 hash

### 8. 평가표 판정

`E:\1_Data\docs\my_trading_logic_acceptance_criteria.md` 기준으로 아래 항목을 평가한다.

| 항목 | 배점 |
|---|---:|
| 재현성 | 20 |
| 리스크 차단 / STOP 능력 | 20 |
| 설명 가능성 | 15 |
| 손실 원인 추적성 | 15 |
| 데이터 정합성 | 10 |
| 운영 자동화 / 유지보수성 | 10 |
| 수익성 / 기대값 | 10 |
| 합계 | 100 |
