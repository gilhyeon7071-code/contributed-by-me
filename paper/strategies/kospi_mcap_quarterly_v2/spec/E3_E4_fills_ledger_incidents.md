## E3 체결 확인 (`sync_fills`)

| 규칙 | 값 | 왜 |
|---|---|---|
| 귀속 키 | 주문 로그의 `broker_order_no` = 조회 `odno` | 종목·방향으로 맞추면 같은 계좌의 다른 체결이 섞인다(확인된 사실 E1~E3) |
| 새 체결 | 누적 `tot_ccld_qty`·`tot_ccld_amt` 의 **증가분** | 조회는 누적값만 준다 |
| 체결 ID | `order_id|누적수량` | 같은 조회를 다시 돌려도 같은 결과(멱등) |
| 기록 | 날짜 없는 append-only `fills.jsonl` | 30일 정리 대상이 아님 |
| 상태 | 누적 = 주문수량 → `FILLED`, 그 밖 → `PARTIALLY_FILLED` | E2 상태기계 |
| 조회에 없음 | `missing` 목록(사고 아님) | 조회 지연일 수 있다 |
| 남의 주문 행 | `orphans` 개수만 | 공유 계좌(카나리아 등) |

사고로 멈추는 것(`status=STOP`)

| 종류 | 조건 |
|---|---|
| `BROKER_ROW_MISMATCH` | 같은 주문번호인데 종목·방향·수량이 다름 |
| `OVERFILL` | 누적 체결 > 주문수량 |
| `FILL_DECREASED` | 누적 체결이 이전 기록보다 작음 |
| `FILL_AFTER_TERMINAL` | 취소·완료로 끝난 주문에 새 체결 — 체결은 **기록하고** 사고로 올린다(돈은 움직였다) |
| `CANCEL_NOT_CONFIRMED` | 취소로 적었는데 조회상 잔량이 남고 취소 표시가 없음 — **필드 동작은 09-22 확인 전 가정** |

## E4 원장 (`build_ledger`) — 체결 로그에서 매번 처음부터

| 항목 | 산식 | 출처 |
|---|---|---|
| 매수 현금 유출 | 체결금액 × (1 + 수수료율) | 수수료율 0.015% **Claude 제안**, 09-22 시험으로 확인 |
| 매도 현금 유입 | 체결금액 × (1 − 수수료율 − 매도세 0.2%) | 매도세: 확인된 사실 E4 |
| 경제적 현금 | 체결 즉시 반영 | NAV 용 |
| 결제 완료 현금 | 체결일 + 2 거래일(`HolidayManager.next_trading_day` 두 번) 이 되면 반영 | 09-17 낙폭 −96.9% 오탐의 원인이 이 구분의 부재 |
| 평단 | 매수원가(수수료 포함) 누적, 매도 시 평단으로 차감 | — |
| NAV | 경제적 현금 + Σ 보유 × 평가가격 | 평가가격이 하나라도 없으면 `INCOMPLETE`, NAV 없음 |
| 보유보다 많이 팜 | `NEGATIVE_POSITION` → `INCOMPLETE` | 불가능한 상태 |

## 영구 중단 래치 (`evaluate_latch`)

- 조건: **완전한** NAV ≤ 전략 자본 × 0.75 (시스템 정의 −25%). 경계값 같음 → 켬
- 켜지면 `latch.json` 파일로 남고 **자동으로 풀리지 않는다**. 이후 매수 단계는 `LATCH_ACTIVE_NO_BUY` 로 멈춤
- NAV 가 불완전하면 판정하지 않는다(모르는 값으로 켜지도 끄지도 않음)
- 래치 후: **다음 거래일부터 전량 매도, 자동 재개 없음**(사용자 09-17 승인) — `run_execution_day liquidate`

## 사고 4종 (`incidents.py`, 시스템 정의 R10)

| 번호 | 함수 | 우는 조건 |
|---|---|---|
| 1 의도≠결과 | `intent_vs_result` | 목표 수량 ≠ 원장 수량이고 설명(부분취소 등)이 없음 |
| 2 조용한 실패 | `silent_failures` | 있어야 할 산출물이 없거나 기준 시각보다 낡음 |
| 3 무단 정지 | `unauthorized_halts` | 매매해야 할 날짜에 실행 기록이 없음 |
| 4 정의 위반 | `definition_violations` | 허용 집행일 밖 주문 / 래치 뒤 매수 / 종목 비중 > 상한×노출 + 1%p |

1%p 허용폭은 **Claude 설정**(사용자 09-17 승인). 비중 판정은 **집행 직후에만**(`post-exec-check`) — 분기 사이 가격 상승으로 20% 를 넘는 건 정상.
